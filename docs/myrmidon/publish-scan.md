# Публикация PR и задач через обёртку со сканером

Боты публикуют тексты PR и задач только через обёртку `scripts/myrmidon/publish-scan.mjs`.
gitleaks смотрит коммиты; текст описаний PR и задач остаётся без проверки — обёртка
закрывает этот пробел: текст прогоняется тем же набором правил, что и диффы
(см. [plan-intake.md](plan-intake.md) и CONVENTIONS.md, раздел 9).

## Когда использовать

- бот публикует или обновляет описание PR (тело PR, комментарии);
- бот создаёт или обновляет текст задачи;
- бот постит отчёт, содержащий выдержки из логов или конфигов.

Прямая публикация текста без обёртки запрещена для ботов. Человек перед PR проходит
самопроверку по CONVENTIONS.md (раздел 9) — обёртка не отменяет её.

## Как использовать

```sh
# текст в файле:
node scripts/myrmidon/publish-scan.mjs --file pr-body.md
# или через stdin:
cat pr-body.md | node scripts/myrmidon/publish-scan.mjs
```

- `exit 0` — публикация разрешена;
- `exit 1` — публикация запрещена: в тексте секрет или внутренний адрес;
- `exit 2` — ошибка чтения или аргументов.

В stdout печатается краткий отчёт: сколько строк отсканировано, сколько находок и
каких типов (`rule xN`). Значения находок не печатаются.

## Схема работы бота

1. Подготовить текст (тело PR или задачи) во временный файл.
2. Прогнать обёртку. `exit 0` — публиковать. `exit 1` — не публиковать: переписать
   текст, убрав секреты и внутренние адреса (имя переменной без значения, номер
   строки, описание сбоя — см. [plan-intake.md](plan-intake.md), раздел 6), и
   прогнать снова. Повторный отказ — эскалация человеку.
3. После публикации текст считается проверенным; при редактировании — прогон заново.

## Что ищет сканер

Присваивания `password/passwd/secret/token/api_key`, заголовки приватных ключей,
префиксы токенов (`github_pat_`, `ghp_`, `pcp_`, `sk-`), частные адреса (`10/8`,
`172.16/12`, `192.168/16`, `100.64/10`), пути к секретам (`/etc/.../secret`,
`~/.ssh/`). Список правил — в `scripts/myrmidon/scan-text.mjs`.

## Тесты

```sh
node --test scripts/myrmidon/publish-scan.test.mjs
```

Обёртка использует тот же сканер, что и пункт PLAN-INTAKE (`scan-text.mjs`):
при слиянии веток файл общий.
