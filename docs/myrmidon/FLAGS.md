# Выключатели Myrmidon (L1–L5)

Единая таблица семантики флагов-выключателей Myrmidon: что значит «включено» и «выключено»
для каждого. Семантика закреплена тестом
`server/src/myrmidon/flags-killswitch.myrmidon.test.ts`: новый флаг с другой семантикой,
потерянная строка или строка без уровня — тест красный.

Подробное описание каждого флага (что делает, как появился, что возвращает вендорское
поведение) — в `SETTINGS.md` соответствующего трека. Здесь — только семантика значений.

## Общие правила

- **Умолчание — поведение нашего развёртывания** (исправление дефекта включено),
  `CONVENTIONS.md` §8. «Выключено» почти всегда возвращает вендорское поведение.
- **Аварийная сторона** — то, куда флаг не должен попадать из-за опечатки. Значение
  опечатки трактуется так, чтобы флаг остался на безопасной (нашей) стороне: аварийный
  откат требует явного и точного значения, без «угадываний».
- Регистр не учитывается при чтении булевых значений; ведущие/хвостовые пробелы
  обрезаются. «Пусто» — переменная не задана, или пустая строка, или одни пробелы.

## Таблица семантики

| Переменная | Уровень | «Включено» значит | «Выключено» (0/false/off/no) значит | Не задано (умолчание) | Опечатка/неизвестное значение |
|---|---|---|---|---|---|
| `MYRMIDON_INFRA_INTERRUPT_CODES` | L1 | Список кодов `agent_paused,process_lost,server_shutdown_interrupted,issue_reassigned` действует: эти обрывы не создают замок разбора, прогон дорабатывает или перепоручается | Пусто или `off` — пустой список, вендорское поведение: замок ставится всегда | Список по умолчанию (исправление включено) | Список не-`off` целиком заменяет умолчание (не добавляется к нему); пустая строка = выключено |
| `MYRMIDON_SETTLED_HOLDS_BLOCK_EXPLICIT_WAKES` | L2 | **Только точное значение `1`** — вендорское поведение: закрытый «no-replay» замок блокирует и явные побудки человека | Наше поведение: замок пропускает явно авторизованные человеком побудки (останавливает лишь автоматический повтор) | Наше поведение (выключено) | `true`, `yes`, `on`, `1 `, `01` — НЕ включает: остаётся наше поведение. Аварийный откат — только явная `1` |
| `MYRMIDON_PAUSE_DRAINS` | L3 | Наше поведение: пауза оператора даёт активным прогонам доработать (drain); отмена — только явным `cancelActive`/`force=1`. Любое значение, кроме явного выключения | Вендорское поведение: пауза всегда отменяет активные прогоны (`agent_paused`) | Включено (наше поведение) | Трактуется как включено: опечатка не должна молча вернуть всегдашнюю отмену прогонов |
| `MYRMIDON_STRANDED_AUTOPOLICY_ENABLED` | L4 | Наше поведение: вся политика L4 — до N повторов исполнителю, затем эскалация руководителю. Любое значение, кроме `false`/`0` | Вендорское поведение: эскалация владельцу сразу, `…RETRIES_PER_DAY` не читается | Включено (наше поведение) | Трактуется как включено: «опечатка не гасит защиту молча» |
| `MYRMIDON_WRITE_LOCK_REQUIRES_LIVE_RUN` | L5 | Наше поведение: блокировка записи 409 требует живого прогона (queued, running, scheduled_retry). Любое значение, кроме `0` и `false` | Вендорское поведение: блокировка только по статусу задачи `in_progress`, живость прогона не проверяется | Включено (наше поведение) | Трактуется как включено: только точное `0`/`false` выключает |

## Заметки по семантике

- **L1 — список, не булев флаг.** Значение — коды через запятую. `off`/пусто — «выключено»
  (вендорский замок), не задано — список по умолчанию из четырёх кодов. Точечный
  «аварийный откат» L1 — `MYRMIDON_INFRA_INTERRUPT_CODES=off`: замок вендора возвращается
  для всех кодов сразу.
- **L2 — единственный «инвертированный» флаг**: умолчание — наше поведение, а аварийный
  откат к вендорскому — включение. Поэтому его включение требует точного значения `1`:
  все прочие значения, включая правдоподобные `true`/`yes`/`on`, оставляют наше
  поведение. Это осознанная защита от случайного включения аварийного режима.
- **L3, L4, L5 — булевы «исправление включено по умолчанию»**: выключение явное
  (`0`/`false`/`off`/`no` — у L3 расширенный набор, у L4/L5 только `0`/`false`),
  всё остальное (включая пусто и не задано) — включено.
- Значение с пробелами вокруг (`" 1 "`, `" 0 "`) обрезается до сравнения — пробелы
  не меняют семантику.
