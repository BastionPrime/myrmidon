# Администратор доски: переключатель в карточке агента и страница прав

> English version: [agent-board-admin.md](agent-board-admin.md)

**Администратор доски** — агент, которому организация доверяет права
администрирования доски: участников компании, роли, гранты прав и настройки
компании. PR #411 (1.6.1 ADMIN-AGENT, часть C) дал этому состоянию лицо в
интерфейсе доски — переключатель в карточке агента и заметную строку на
странице прав. Это руководство описывает обе поверхности.

## Где живёт переключатель

Вкладка **Permissions / Trust** карточки агента (блок Governance навигации
карточки, `/agents/<agent>/permissions`). Внутри рамки **Permissions**, под
тремя существующими флагами (**Can create new agents**, **Can create/import
skills**, **Can assign tasks**) идёт четвёртая строка **Board administrator**
с подсказкой:

> Lets this agent administer the board: members, permissions and company
> settings. An agent cannot change this state for itself.

## Что делает переключатель

Переключение отправляет тот же вызов `PATCH /agents/:id/permissions`, что и
три соседних флага, с `boardAdmin` рядом с базовыми флагами. Состояние
переключателя приходит из API карточки агента: значение `access.boardAdmin`,
которое резолвит сервер, с откатом на сохранённый эхо-флаг
`permissions.boardAdmin`. Оба читателя fail-closed: любое значение, кроме
`true` (отсутствует, битое, legacy), читается как **не** администратор доски,
поэтому старый сервер или устаревший кэш никогда не заставит интерфейс
показать или переключить админские права, которых нет.

Сам контракт прав — какие гранты флаг реально выдаёт, снимок ранее
существовавших грантов, запрет само-включения, журнал действий — это
серверная половина функции (часть A, отдельный мерж); пока она не влита, флаг
хранится и показывается, но полномочий оператора ещё не несёт.

## Что гранты дают за пределами карточки

Грант, выданный переключателем, — настоящий грант везде, где сервер его
проверяет, а не только на экранах прав. С `agents:configure` агент может
ставить агентов на паузу и снимать с неё (`POST /agents/:id/pause` и
`/resume` пропускают агентских актёров через одну и ту же лесенку прямых
грантов, так что одного `agents:suggest-changes` недостаточно). Пауза,
выставленная агентом, пишется в журнал под его собственным идентификатором
(агент, прогон и API-ключ), а не под заглушкой доски.

## Кто видит переключатель

Сводка доступа оператора не несёт явного флага `users:manage_permissions`,
поэтому доступность выводится из роли оператора в компании:

| Оператор | Видит переключатель |
|---|---|
| Локальная неявная доска (local_implicit) | да |
| Администратор инстанса | да |
| Роль участия в компании `owner` | да |
| Роль участия в компании `admin` | да |
| Роль `operator` или `viewer` | нет — раздел скрыт целиком |

Если API всё же отвечает 403 (само-переключение или более строгое серверное
правило), под переключателем появляется человеческое объяснение вместо
сырой ошибки, например для само-переключения:

> An agent cannot change its own board administrator state. Ask another board
> administrator to change it.

## Страница прав

Страница участников в настройках компании (**Members**, маршрут
`/company/settings/members`, сайдбар Company Settings → Members) теперь
называет каждого агента-администратора доски. Таблица участников рисует
по одной строке на каждого агента со статусом
отличным от `terminated` и истинным флагом, над строками
людей-участников: аватар и имя агента (ссылка сразу на вкладку
**Permissions** карточки агента), длинное тире в колонке Email, метку роли
агента с контурным бейджем **Board administrator**, бейдж статуса и ссылку
**Permissions** в колонке Action. Агенты без флага строки не получают;
terminated агент с флагом тоже не попадает в список. Если нет ни участников,
ни агентов-админов, таблица показывает обычное пустое состояние; строки
агентов сами по себе его тоже гасят.

## Чего в части C нет

Нет интерфейса для отзыва или просмотра грантов, в которые флаг отображается,
кроме самого переключателя, и страница прав не показывает гранты агента-админа
детально — только метку роли и бейдж. PATCH прав из карточки агента —
единственный путь записи.
