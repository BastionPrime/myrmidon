# Задача закрывается сама, когда её пулл-реквесты слиты (TASK-PR-SYNC)

> English version: [task-pr-sync.md](task-pr-sync.md)

Задача, которую доставляет пулл-реквест, раньше оставалась `in_progress`,
пока кто-нибудь не замечал слияние и не закрывал задачу руками. Теперь доска
закрывает её сама: периодический проход следит за пулл-реквестами,
зарегистрированными на задаче, и, когда все они завершились и хотя бы один
слит, переводит задачу в `done`. Возможность поставляется включённой и
настройки не требует.

## Откуда у задачи её PR

Проход не заводит параллельного хранилища: он читает собственные рабочие
продукты задачи — те же продукты `pull_request`, которые доска записывает,
когда агент или прогон регистрирует доставляющий пулл-реквест
(`POST /api/issues/:id/work-products`, тип `pull_request`, провайдер
`github`). На задаче может быть несколько PR (по одному на часть работы);
проход резолвит каждый через существующий резолвер GitHub со скоупом
компании и не добавляет своего токена или креденшела.

## Что делает один проход

Проход идёт на тике планировщика, не чаще раза в минуту
(`MYRMIDON_TASK_PR_SYNC_POLL_SEC`, по умолчанию 60). Один проход осматривает
не больше `MYRMIDON_TASK_PR_SYNC_BATCH_MAX` задач-кандидатов (по умолчанию
50), сначала те, что дольше не менялись (`updatedAt`), и не идёт вовсе, пока
инстанс в обслуживании. Для каждого кандидата он резолвит каждый PR через
существующий резолвер GitHub, обновляет сохранённую строку рабочего
продукта, если резолвер сдвинул её состояние, и затем решает:

| Состояние задачи после прохода | Что делает доска |
|---|---|
| Все PR терминальны, хотя бы один слит, открытых гейтов после выката нет | Закрывает задачу: статус `done`, один нейтральный комментарий, строка журнала, ожидающий рабочий процесс исполнения задачи распускается |
| Все PR терминальны, ни один не слит | Возвращает задачу в `in_progress` с комментарием, если только комментарий новее закрытия уже не ответил на него |
| Какой-то PR ещё открыт или в драфте | Не трогает задачу (работа не закончена) |
| Состояние PR не удалось резолвить | Не трогает задачу (отказ резолвера никогда не читается как слияние) |
| Задачу держит открытый гейт после выката | Не трогает задачу до разрешения гейта (см. ниже) |

Терминальные состояния PR — `merged` и `closed`; строки с
superseded (архивные) игнорируются — дубль, который обогнала замена, не
должен держать задачу открытой. Старый PR, закрытый без слияния, за которым
последовала слитая замена, закрывает задачу: хотя бы одного слитого PR
достаточно, чтобы считать работу доставленной.

## Комментарии закрытия и возврата

Закрытие пишет ровно один комментарий от системного актёра `task_pr_sync`:

```text
Delivered: PR itkadr-git/myrmidon#315 merged (8a5ac6f48c4823ac76b626aadb77830f18394a41); task closed by the periodic PR sync at 2026-10-02T15:57:20.000Z.
```

а путь возврата пишет:

```text
Delivery pending: PR itkadr-git/myrmidon#315 was closed without merging; task returned to the assignee at 2026-10-02T15:57:20.000Z.
```

SHA слияния записывается на каждый слитый рабочий продукт
(`metadata.lastMergedSha`), поэтому повторный проход, который каким-то
образом снова увидит то же слияние, не пишет второй комментарий. Закрытие
идёт тем же путём `issueService.update`, что и ручной PATCH доски; SQL
руками не пишется.

## Гейты после выката

У человека может оставаться решение уже после слияния. Проход откладывает
закрытие, пока на задаче открыт гейт после выката:

- ожидающая интеракция в треде задачи (карточка ревью или подтверждения),
- ожидающее согласование или согласование с запросом правок,
- монитор, запланированный на будущее (`executionPolicy.monitor.nextCheckAt`).

Когда гейт разрешится, следующий проход закроет задачу.
`MYRMIDON_TASK_PR_SYNC_SETTLE_DISABLED` — грубый рычаг на весь инстанс:
проход продолжает читать и журналировать, но никогда не переводит задачу в
`done`, — для намеренной удержки всех закрытий разом; на проверку
пертасковых гейтов он не влияет.

## Журнал активности

Каждое автоматическое действие пишет строку журнала (актёр `task_pr_sync`):

| Действие | Когда |
|---|---|
| `myrmidon.task_pr_sync.settled` | Проход закрыл задачу (ссылки на PR, SHA слияний и прежний статус — в деталях). |
| `myrmidon.task_pr_sync.returned` | Проход вернул задачу исполнителю (ссылки на закрытые PR и прежний статус — в деталях). |

## Сторож побудок (половина допуска)

Перед диспатчем прогона по бессобытийной побудке доска проверяет, не
терминальны ли уже все продукты `pull_request` задачи с хотя бы одним
слитым — и задача ещё не закрыта. Если да, побудка пропускается (заявка
прогонов со статусом `skipped` и причиной
`wake_skipped_pr_settle_pending`)
вместо того, чтобы жечь прогон, который лишь гонялся бы с закрытием: задачу
закроет следующий тик прохода. Побудки с событиями — человеческий
комментарий или интеракция в треде — никогда не подавляются. Настройки:
`MYRMIDON_TASK_PR_SYNC_WAKE_GUARD_*` в [../SETTINGS.ru.md](../SETTINGS.ru.md).

## Настройки

Возможность поставляется включённой; выключает её только явное значение
«выкл», чтобы опечатка не погасила фикс молча.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MYRMIDON_TASK_PR_SYNC_ENABLED` | `1` (вкл) | Полный выключатель прохода. `0`/`false`/`off`/`no` выключает его (задачи остаются занятыми до закрытия руками) |
| `MYRMIDON_TASK_PR_SYNC_POLL_SEC` | `60` | Минимальный промежуток между двумя проходами; сама очередь планировщика тикает чаще |
| `MYRMIDON_TASK_PR_SYNC_BATCH_MAX` | `50` | Сколько задач-кандидатов один проход осматривает максимум |
| `MYRMIDON_TASK_PR_SYNC_SETTLE_DISABLED` | не задана (закрытие включено) | Удержка на весь инстанс: проход читает и журналирует, но не переводит задачи в `done` |
| `MYRMIDON_TASK_PR_SYNC_WAKE_GUARD_ENABLED` | `1` (вкл) | Полный выключатель сторожа побудок. `0`/`false`/`off`/`no` выключает его (побудки запускают прогоны, как раньше) |
| `MYRMIDON_TASK_PR_SYNC_WAKE_GUARD_TTL_SEC` | `60` | Сколько решение о подавлении живёт в кеше для одной задачи (кеш держит максимум 1000 задач, вытеснение наименее давних) |

Подробности и полная таблица настроек: [../SETTINGS.ru.md](../SETTINGS.ru.md).
