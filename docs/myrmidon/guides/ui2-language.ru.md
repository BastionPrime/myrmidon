# Язык интерфейса 2.0 (UI2-I18N)

> Английская версия: [ui2-language.md](ui2-language.md)

Интерфейс 2.0 двуязычен: английский — база, русский — полный перевод. Каждый
человек выбирает язык один раз; доска помнит выбор на сервере за этим
человеком, поэтому язык следует за пользователем в любой браузер и на любую
машину. Возможность не требует настройки и настроек не имеет.

Возможность живёт в дереве интерфейса 2.0 за флагом экземпляра
`enableMyrmidonUi2` (по умолчанию выкл., настройки инстанса → Experimental →
«Myrmidon UI 2.0 Shell»). Экраны 1.x она не переводит; их русский перевод —
отдельный трек (UI-RU).

## Где пользователь выбирает язык

Экран «Язык» оболочки 2.0: Настройки → Язык
(`/company/settings/language`, ключ маршрута `settings-language`). Экран
показывает два поставляемых языка — английский и русский — как группу
радио-кнопок (каждый пункт подписан собственным именем языка, «English» /
«Русский»), плюс живой предпросмотр навигации и карточки решения на
выбранном языке, чтобы выбор был виден до его применения.

Честная граница перевода показана на том же экране:

- Тексты, написанные агентами (тела задач, логи прогонов, комментарии), не
  переводятся. Настройка выбирает каталог, из которого рисуется каркас
  интерфейса, а не перевод содержимого.
- Идентификаторы (номера задач, имена агентов) не меняются.
- Отсутствующая русская строка подставляется английской базой.

## Как выбор сохраняется

Настройка — персональная, в рамках инстанса, хранится на сервере — тот же
паттерн, что у настроек сайдбара: ключ по идентификатору пользователя,
вне компаний, агентами не пишется.

Таблица `user_ui_language` (миграция `0289_nice_shiva`, только аддитивно:
одна новая таблица и уникальный индекс по `user_id`) хранит одну строку на
пользователя со значением `en` или `ru`. Пользователю, никогда не
сохранявшему выбор, отвечает английский.

В браузере последний применённый выбор зеркалится в `localStorage`
(`myrmidon:ui2:language`). Это держит язык через перезагрузку до ответа
сервера и через неответивший запрос. Копия сервера всё же выигрывает при
загрузке — кроме случая, когда пользователь уже переключил язык в текущей
сессии: тогда его более новый выбор не перезаписывается. Смена языка в
одной вкладке применяется в остальных вкладках того же браузера (синк по
storage-событию).

Неудачная запись на сервер не откатывает язык: выбор остаётся применённым
в этом браузере, а экран помечает, что серверная копия не сохранилась.
Офлайн или вне board-сессии используется локальное зеркало.

Провайдер также ставит атрибут `lang` (`en`/`ru`) на корневой элемент
интерфейса 2.0 (`.myr-ui2`). Этот атрибут — весь шрифтовой контракт с темой
оболочки: Saira для английского, Exo 2 для русского, по правилу
`[lang="ru"]` в токенах темы.

## Что покрывают каталоги ui2

Каталоги живут в `ui/src/ui2/i18n/catalogs/{en,ru}.ts` и регистрируются на
экземпляре i18next в отдельном namespace `ui2` — вендорские файлы локалей
не трогаются. Namespace `ui2.*` покрывает только дерево 2.0: каркас
оболочки, экраны, переработанные в дереве 2.0, и сам экран языка. Остальные
38 вендорских локалей получают английские значения по цепочке фолбэков,
пока до них не дойдёт проход перевода.

Два правила держат сторож-тесты, а не договорённость:

- `ui/src/ui2/i18n/no-english-in-ru.myrmidon.test.ts` — статический скан
  дерева 2.0 падает на захардкоженные пользовательские строки (текст JSX и
  атрибуты `title`/`aria-label`/`placeholder`/`label`/`alt`) и на `t()`-ключи,
  которых нет в обоих каталогах.
- `ui/src/ui2/i18n/catalog-parity.myrmidon.test.ts` — паритет ключей между
  `en` и `ru`, непустые русские значения, не оставленные английскими
  (кроме алоу-листа), и совпадение плейсхолдеров интерполяции.

## Эндпоинт API (для операторов)

Настройка открыта двумя маршрутами, только для board-пользователей:

```
GET /api/myrmidon/ui2/language/me
200 { "language": "en" | "ru", "updatedAt": <время> | null }

PUT /api/myrmidon/ui2/language/me
тело: { "language": "en" | "ru" }
200 { "language": ..., "updatedAt": <время> }
```

- Маршрут не несёт идентификатора компании: настройка одна на пользователя
  в рамках инстанса.
- Сессия не от board-пользователя (ключ агента или board-актор без
  идентификатора пользователя) получает `403` на чтение и запись — агенты
  не читают и не пишут настройку.
- Тело с неизвестным кодом языка или без поля `language` получает `400`.
- `PUT` сохраняет значение и пишет одну запись журнала активности
  (`myrmidon.ui2.language_updated`) на каждое активное членство
  пользователя в компании, с прежним и новым значением, чтобы изменение
  попадало в журнал аудита каждой компании так же, как прочие настройки
  доски. Пользователь без членств получает запись без строк аудита.

Это настройка, принадлежащая интерфейсу; доска не локализует через неё свой
API и полезную нагрузку для агентов.
