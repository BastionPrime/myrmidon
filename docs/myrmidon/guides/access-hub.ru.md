# Хаб доступов (Access hub)

> English version: [access-hub.md](access-hub.md)

Access hub — раздел настроек (Настройки → Access hub, маршрут
`company/settings/access-hub`, пункт бокового меню сразу после Secrets) для
секретов, которыми пользуются агенты, хосты и сервисы: кто держит реквизиты,
где они используются, когда их последний раз меняли.

Раздел использует тот же ключ видимости оператора, что и Secrets: пункт
появляется в боковом меню настроек только там, где видна сама страница Secrets.

## Текущее состояние выката

Прочтите этот раздел первым — он описывает, что слитый код реально делает
сейчас.

Раздел выкатан двумя частями с **разными контрактами обмена**:

- Интерфейс (экран, список, карточка и диалоги) вызывает
  `POST /secrets`, `POST /secrets/generate-ssh`, `POST /accesses/:id/grant`,
  `POST /accesses/:id/revoke`, `POST /accesses/:id/rotate`, `PUT /hosts` и
  `GET /audit` под `/api/myrmidon/access-hub` и ждёт список доступов
  массивом.
- Серверный модуль отдаёт под тем же префиксом другую поверхность:
  `POST /secrets/generate-ssh-key`, `POST /secrets/:id/rotate-ssh-key`,
  `POST /secrets/:id/kind`, `POST /accesses/grant` и `POST /accesses/revoke`
  без параметра в пути, `GET /secrets/:id/bindings`, `GET /journal`, полный
  CRUD реестра хостов и `GET /status`, а список доступов заворачивает в
  объект (`{ enabled, accesses, hosts }`).

В результате на инсталляции с этим серверным модулем экран не падает в
уведомление «пока недоступно» (проба доступности считает «API нет» только
ответы 404/501), но вызов списка возвращает форму, которую страница не ждёт,
а все изменяющие кнопки вызывают маршруты, которых на сервере нет. Сквозные
сценарии, описанные ниже, поэтому **пока не работают**; описание фиксирует,
для чего каждая кнопка предназначена. Сам серверный API, вызванный напрямую
со своими маршрутами, работает за флагом функции.

Ещё два факта о выкате:

- Серверный модуль стоит за `MYRMIDON_ACCESS_HUB_ENABLED` (по умолчанию
  `false`; см. [SETTINGS.md](../SETTINGS.md)). Пока флаг выключен, читающие
  эндпоинты отвечают `enabled: false` с пустыми данными и не трогают
  хранилище, а изменяющие отказывают с 409 (`access_hub_disabled`).
- Раскладка SSH-ключа на хост — пока фиктивный порт деплоя: сервер записывает
  набор хостов в метаданные секрета и журналирует операцию, но реального
  SSH-подключения не делает (настоящий клиент — следующая часть). На хост
  вообще должна попадать только публичная половина ключа.

## Единственное правило секретности

Значения секретов не отображаются никогда. Список, карточка и журнал
показывают только имена, ссылки, версии и публичный отпечаток SSH — колонки со
значением нет нигде в разделе. Единственный кусочек материала реквизитов,
который интерфейс вообще показывает, — публичная половина только что
сгенерированной пары SSH-ключей: она держится в памяти страницы, пока открыта
её карточка (или диалог генерации), а повторно открытая карточка показывает
только отпечаток. Значение, введённое в диалог записи, отправляется один раз,
никогда не возвращается из API и стирается из формы, как только сохранение
завершается.

То же правило держит и сервер: ответы списка и журнала не несут поля значения,
приватная половина сгенерированного ключа уходит в существующее хранилище
секретов компании через существующий путь create/rotate и никогда не выходит
из него через ответ access-hub, а публичная половина возвращается ровно один
раз — в ответе генерации (или ротации ключа).

## Список доступов

Список показывает все доступы, которые сообщает сервер, по строке на доступ:

| Колонка | Содержимое |
|---|---|
| Name | Имя и ключ доступа |
| Type | `SSH key`, `Password`, `Token` или `OAuth` |
| Granted to | Агенты, которым доступ выдан |
| Used by | Хосты и сервисы, которые его используют |
| Created | Время создания (UTC) |
| Rotated | Время последней ротации (UTC), `—`, если ни разу |
| Version | Номер текущей версии, `v<N>` |

Список фильтруется свободным поиском (имя, ключ, имена держателей и
использований), по типу и по агенту, которому доступ выдан.

## Карточка доступа

Открытие строки показывает карточку с полной картиной одного доступа: версия,
время создания и последней ротации, публичный отпечаток SSH для ключей, агенты,
которым доступ выдан, хосты и сервисы, которые его используют (с путём
конфигурации, где стоит ссылка), и набор хостов. Поля со значением в карточке
нет.

Действия в карточке:

- **Change value** — заменить значение секрета. Новое значение вводится в
  диалог, отправляется один раз и никогда не показывается обратно.
- **Rotate** — ротировать доступ (см. ниже).
- **Generate new key** — для SSH-доступов сгенерировать новую пару ключей
  (см. ниже).
- **Deploy to hosts** / **Withdraw from hosts** — изменить набор хостов
  парка, на которых лежит этот доступ.
- **Grant** / **Revoke** — выдать доступ агенту или отозвать его. Выдача —
  это ссылка: агент получает доступ к секрету, а не копию его значения. На
  сервере выдача — строка в существующей таблице привязок секретов
  (`targetType: "agent"`, `configPath: "env"`), которую существующий
  компилятор профиля разрешает в окружение контейнера агента.

## Ротация

У диалога ротации два режима:

- **External source** — значение изменилось вне Myrmidon; записывается новая
  версия без введённого значения.
- **New value** — введите новое значение; оно записывается один раз и никогда
  не возвращается.

В обоих режимах есть «Restart the containers that use this access» (включено
по умолчанию), чтобы каждый перезапущенный контейнер получил новое значение;
всплывающее уведомление о результате сообщает номер новой версии и имена
перезапущенных контейнеров.

Замечание про текущее состояние выката: слитый сервер реализует ротацию для
SSH-ключей (`POST /secrets/:id/rotate-ssh-key` — генерируется свежая пара,
приватная половина становится новой версией, новая публичная половина
возвращается один раз). Общего маршрута ротации, который вызывает диалог
(`POST /accesses/:id/rotate`), и перезапуска контейнеров, который он
предлагает, в слитом сервере пока нет.

## Генерация SSH-ключа

Диалог генерации создаёт новую пару SSH-ключей как доступ. Дайте ключу имя и
при желании выберите хосты из реестра хостов парка.

На сервере генерация создаёт пару ed25519: приватная половина становится
значением нового секрета через существующий путь создания, публичная половина
и её отпечаток (`SHA256:…`, форма OpenSSH) возвращаются один раз в ответе, а
выбранные хосты записываются в метаданные секрета. Публичная половина и её
отпечаток показываются один раз, в этом диалоге, — скопируйте публичный ключ
на каждый выбранный хост сразу. На карточке после этого остаётся только
отпечаток; повторно открытая карточка показывает один лишь отпечаток.

## Журнал

Таб «Журнал» показывает, кто какого доступа коснулся, когда и какая версия из
этого вышла: создание, выдача, отзыв, ротация и раскладка доступов попадают
сюда. Строки журнала несут имена и версии — никогда значения. Таб показывает
50 последних строк.

На сервере журнал — это лог активности, отфильтрованный по действиям
`access_hub.*`, новые сначала, с лимитом по умолчанию 100 записей (максимум
500).

## API

Серверный модуль отдаёт `/api/myrmidon/access-hub/*`, только для доски, за
`MYRMIDON_ACCESS_HUB_ENABLED`:

| Маршрут | Назначение |
|---|---|
| `GET /status` | Включён ли модуль на этой инсталляции |
| `GET /accesses` | Список доступов с реестром хостов: `{ enabled, accesses, hosts }` |
| `POST /secrets/generate-ssh-key` | Сгенерировать пару SSH-ключей ed25519 как новый секрет; публичная половина возвращается один раз |
| `POST /secrets/:id/rotate-ssh-key` | Ротировать секрет-ключ SSH на свежую пару; новая публичная половина возвращается один раз |
| `POST /secrets/:id/kind` | Задать тип секрета (`ssh_key` / `password` / `token` / `oauth`) и SSH-метаданные |
| `POST /accesses/grant` | Выдать секрет агенту (тело: `secretId`, `agentId`) |
| `POST /accesses/revoke` | Отозвать секрет у агента (то же тело) |
| `GET /secrets/:id/bindings` | Привязки одного секрета (кто его держит) |
| `PUT /accesses/:id/hosts` | Задать набор хостов секрета-ключа SSH (раскладка/снятие — одна set-запись) |
| `GET /journal` | Записи журнала, новые сначала (параметр `limit`, по умолчанию 100, максимум 500) |
| `GET /hosts`, `POST /hosts`, `PATCH /hosts/:hostId`, `DELETE /hosts/:hostId` | Реестр хостов парка (общий на инсталляцию, не более 200 хостов) |
| `POST /hosts/:hostId/deploy/:secretId` | Разложить один SSH-ключ на один хост (пока фиктивный порт деплоя) |

Пути не несут `:companyId`: компания берётся сначала из параметра запроса
`companyId`, затем из единственного активного членства вызывающего; ноль или
несколько членств без параметра отвечают 422.

Значения секретов никогда не уходят обратно по этому API: записи не несут
поля значения, а единственное введённое оператором значение записи никогда не
возвращается в ответе.

## Вопросы и ответы

**Я потерял значение. Можно ли его прочитать обратно?**
Нет — так задумано. Ни список, ни карточка, ни журнал, ни ответ API не несут
значения. Задайте новое значение в карточке (**Change value**) или, для
SSH-ключей, ротируйте на свежую пару; затем перезапустите потребителей, чтобы
они подхватили новую версию. (В текущем состоянии выката эти кнопки — среди
тех, что ещё ждут контракт обмена, см. выше.)

**Как проверить, что агент подхватил доступ?**
Выдача — это строка привязки (`targetType: "agent"`, `configPath: "env"`), и
она попадает в журнал (`access_hub.access.granted`). Значение попадает в
окружение контейнера агента через существующий компилятор профиля при старте
контейнера; контейнер, запущенный до выдачи, продолжает работать без него до
следующего старта.

**Что означает значок «soon» на пункте настроек?**
API хаба доступов ответил 404 или 501 — эта инсталляция вообще не обслуживает
маршруты модуля. В этом случае экран показывает одно уведомление «пока
недоступно» и включится сам, когда серверная часть будет развёрнута. Учтите:
проба распознаёт только отсутствующий маршрут; при развёрнутом модуле, но
выключенном флаге функции значок не появляется.
