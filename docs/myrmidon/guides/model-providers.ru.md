# Провайдеры моделей компании (реестр, ключи write-only, кэш моделей)

> Английская версия: [model-providers.md](model-providers.md)

Компания регистрирует model-провайдеров, которыми могут пользоваться её агенты:
OpenAI, DashScope, Google или любой OpenAI-совместимый эндпоинт. Ключ провайдера
держит доска: значение один раз пишется в хранилище секретов компании и больше
никогда не возвращается ни одним эндпоинтом — чтения отвечают только `has_key`.

## Что даёт API

Все маршруты живут под `/api/myrmidon/companies/:companyId/model-providers`:

| Маршрут | Кто | Что делает |
|---|---|---|
| `POST …` | только board | Регистрирует провайдера. `key` обязателен и валидируется опросом `/models` провайдера этим ключом; невалидный ключ → 422, ничего не пишется. Список моделей из успешного опроса становится кэшем провайдера. |
| `GET …` | чтение компании | Список провайдеров: тип, имя, base URL, `has_key`, free/paid, время валидации. Никогда — значение ключа. |
| `PATCH …/:id` | только board | С `key`: ротация (новый ключ сначала валидируется; плохой ключ ничего не меняет). Без `key`: переименование/правка метаданных. |
| `DELETE …/:id` | только board | Удаляет провайдера, его кэш моделей и секрет. |
| `GET …/:id/models` | чтение компании | Кэшированный список моделей, полученный при валидации ключа. |
| `POST …/:id/models` | только board | Включение/выключение моделей (и метки free/paid). |

Каждая мутация пишет запись в журнал активности (`model_provider_added`,
`model_provider_key_rotated`, `model_provider_removed`) с именем и типом
провайдера — никогда со значением ключа.

## Где живёт ключ

Учётные данные лежат в хранилище секретов компании под именем, производным от
id строки провайдера (`model-provider-key-<id>`). Строка в базе хранит только
это имя. Секрет для этого модуля write-only: сервер читает значение только для
валидации при создании/ротации; ни один путь чтения настроек его не разрешает.

## Валидация

`POST` и `PATCH` (ротация) опрашивают OpenAI-совместимый `/models` эндпоинт
провайдера кандидатным ключом до любой записи:

- 401/403 от провайдера → 422 «the provider rejected this key»;
- сетевой сбой → 422 «could not reach the provider»;
- пустой список моделей → 422 (вероятно, неверный base URL).

Успешный ответ кэшируется в `model_provider_models`, по строке на модель, с
`litellm_model_name`, который использует регистрация в шлюзе (часть B).
