# Регламенты компании в вики (черновик → одобрено, ревизии, откат)

> Английская версия: [wiki-regulations.md](wiki-regulations.md)

Регламент — это страница вики, чья аудитория — набор ролей, а не человек: «как
инженеры делают выкат», «что одобряет владелец». Доска — единый источник правил,
которые исполняют агенты, и вики — место, где эти правила пишут и хранят.

Жизненный цикл намеренно односторонен там, где это важно: **правка текста
никогда не меняет то, что читает флот.** Изменение — черновика или
одобренного регламента — добавляет новую ревизию DRAFT, и резолвер продолжает
отвечать последней ОДОБРЕННОЙ ревизией, пока кто-то не одобрит новый текст.
Откат — ещё одна ревизия, копирующая более раннюю, поэтому история остаётся
append-only, а сам откат откатываем.

## Что даёт API

Все маршруты живут под `/api/myrmidon/companies/:companyId/wiki-regulations`:

| Маршрут | Кто | Что делает |
|---|---|---|
| `GET …` | чтение компании | Список всех страниц-регламентов компании (любой статус) с полной историей ревизий. |
| `GET …/approved/:role` | чтение компании | Резолвер: одобренные ревизии, применимые к роли, в том виде, в каком их читает доставка. |
| `GET …/:slug` | чтение компании | Одна страница с её ревизиями. |
| `PUT …/:slug` | запись компании | Сохраняет черновик. Первый раз создаёт страницу; каждое следующее сохранение добавляет ревизию-черновик. |
| `POST …/:slug/approve` | только board | Одобряет последнюю ревизию — единственный способ сделать текст доставляемым. Повторное одобрение — no-op. |
| `POST …/:slug/rollback` | только board | Восстанавливает более раннюю ревизию как новую. Новая ревизия сохраняет статус восстановленной. |

Роли — обычные ключи ролей агентов компании; спецключ `*` означает «все роли».
Пустой список ролей нормализуется в `*`.

Запись черновика открыта агентским действующим лицам компании (википедист
пишет черновики); одобрение и откат — только board, потому что они меняют то,
что читает весь флот. Каждая мутация пишет строку в журнал активности компании
(`wiki.regulation_draft_saved`, `wiki.regulation_approved`,
`wiki.regulation_rolled_back`).

## Как регламент доходит до агентов

Точка доставки — компиляция профиля бота
(`server/src/myrmidon/bot-containers/profile-compile.ts`, метка
`myrmidon(1.6-WIKI)`): на каждом проходе сверки компиляция спрашивает резолвер
по роли агента и рендерит один детерминированный workspace-файл
`REGULATIONS.md` рядом с собственными файлами инструкций агента. Компиляция
детерминирована, и её хэш решает, перезапускается ли бот, поэтому:

- те же одобренные ревизии — те же байты — без перезапуска;
- новая одобренная ревизия меняет хэш, и бот получает новый текст на следующем
  прогоне;
- правка черновика не меняет ничего, что видит флот: доставляемые байты
  строятся только из одобренных ревизий.

Если собственный бандл инструкций агента уже содержит `REGULATIONS.md`, тот
выигрывает, и компиляция записывает предупреждение вместо доставки текста из
вики — вики никогда не перезаписывает собственные файлы агента.

## Как добавить агента-википедиста

Википедист — обычный агент компании, чья задача — держать страницы регламентов
в актуальности: он пишет ревизии-черновики через тот же API, а член board их
одобряет. Доска не поставляет агента; это шаг оператора (контейнеры ботов):

1. Создайте агента компании с **ролью**, которую борд использует для
   википедиста (например `wiki-maintainer`). Ключ роли — то, что страницы
   регламентов смогут назвать позже.
2. Дайте ему бесплатную модель DashScope через LLM-шлюз (правило 1.6: новые
   агенты — только на бесплатных моделях).
3. Направьте его инструкции на API регламентов: можно `GET`-список, `GET`
   страницу и `PUT`-черновик. Одобрять и откатывать он не может — API отвечает
   403 агентским действующим лицам на этих двух маршрутах, инструкции это не
   переопределяют.
4. Одобряйте его черновики с борда, когда текст готов.

Инстанс не требует новых переменных окружения: функция всегда включена и не
имеет настроек.

## Права

- **Чтение и черновик** — любое действующее лицо с доступом к компании.
  Регламент чужой компании неотличим от отсутствующего (404).
- **Одобрение и откат** — только действующие лица board.

## Данные и миграция

Одна строка на регламент в `myrmidon_wiki_regulations` (миграция 0290,
аддитивная: новая таблица с уникальным индексом `(company_id, slug)` и
индексом по статусу). История ревизий живёт в jsonb-колонке `revisions` — по
одной записи на ревизию, старые первыми, каждая со своим статусом, — а новейшая
ревизия отражена в обычных колонках, чтобы список вики не ходил по истории.
