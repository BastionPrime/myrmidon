# Внешние MCP-коннекторы: подключение без кода форка

> Английская версия: [external-mcp-connectors.md](external-mcp-connectors.md)

Доска умеет подключать внешний MCP-сервер, совместимый со стандартом, — любой
HTTP MCP-эндпоинт, которым владеет или которому доверяет компания, — и выдавать
его инструменты выбранным агентам. В этом руководстве нет кода форка: это
вендорская поверхность generic-подключений, описанная здесь, потому что при
планировании считали, что нужна своя точка расширения. Руководство — сдача
функции «generic extension point» и операционный регламент подключения
нового внешнего MCP-сервиса.

## Что уже есть (вердикт разведки)

Вендорская поверхность, сверена с `main` 02.10.2026:

- **Реестр подключений с привязкой к компании.** Строка в `tool_connections`
  (id компании, имя, транспорт `mcp_remote`, `config.url`, статус,
  enabled, здоровье). Заводится без правки кода — через любую из двух точек
  входа ниже.
- **Креды через сервис секретов.** Bearer-ключи, кастомные заголовки,
  OAuth-клиенты — каждое значение становится секретом Paperclip,
  write-only, обратно не отдаётся. `McpConnectionCredentialRef` привязывает
  секрет к подключению; шлюз инструментов резолвит его в момент вызова
  (`server/src/services/tool-gateway.ts`, `secrets.resolveSecretValue`).
- **Гранты по агентам.** Два слоя: installs
  (`tool_connection_installs`, цель `company` или `agent`) и профили
  инструментов (entries по подключению, привязки к агенту/проекту/рутине/
  задаче, `defaultAction: deny`, allowlist по инструментам, ask-first по
  уровням риска). Посторонний агент получает `deny_default` — доказано
  вендорским тестом `gives a generic connection the same review, access,
  install, gateway and revoke path`.
- **Прокси для агентов.** Агенты не ходят в MCP-эндпоинт напрямую: прогон
  несёт назначенный набор инструментов (`resolveAgentAssignedToolSet` в
  `server/src/services/agent-assigned-tools.ts`), каждый вызов идёт через
  шлюз инструментов, где грантовая политика компании решает
  allow/deny/require_approval. Имена инструментов приходят с неймспейсом
  `mcp.<connection>:<tool>` (`connectedMcpToolsForCompany`).
- **Ограждение безопасности.** SSRF/приватные сети с пином DNS
  (`server/src/services/remote-http-endpoint-guard.ts`), allowlist имён
  заголовков (`packages/shared/src/mcp-remote-headers.ts`), валидация OAuth
  эндпоинтов (CIMD, DCR, PKCE) — для generic-подключений всё действует так
  же, как для курируемых.

Чего **не хватает** и у чего нет вендорской поверхности: для выката не
найдено ничего. Приватные эндпоинты по plain HTTP (контейнер коннектора в
сети доски) принимаются, потому что этот деплой работает с
`PAPERCLIP_DEPLOYMENT_MODE=authenticated` и
`PAPERCLIP_DEPLOYMENT_EXPOSURE=private` — в этом режиме гвард допускает
приватные адреса. Инстанс в режиме `authenticated/public` их отвергнет
(`remote_http_private_endpoint`) — и это задокументированное поведение
вендора, а не дыра форка.

## Две точки входа

| Путь | Где | Когда |
| --- | --- | --- |
| Управляемый URL | Apps → Connect an app → **Connect your own MCP server** | Есть адрес сервера; доска пробует его и ведёт по шагам. |
| Вставка конфига | Apps → Advanced → **Paste a config** | README сервиса даёт JSON-сниппет `mcpServers` или нужны кастомные заголовки. |

Оба пути нормализуются через один бэкенд-контракт; авторизация, секреты,
обновление каталога и ревью не могут разъехаться между ними.

Авторитетный документ вендора —
[doc/connections/GENERIC-REMOTE-MCP.md](../../../doc/connections/GENERIC-REMOTE-MCP.md)
в этом же репозитории; там уровни OAuth-клиентов, метка «Unverified server»
и заметки о соответствии протоколу.

## Регламент: подключить новый внешний MCP-сервис

1. **Поднять сервис в сети доски** (свой контейнер; имя docker-сети доски —
   деталь развёртывания). Эндпоинт должен отвечать MCP Streamable HTTP
   (`initialize`, `tools/list`, `tools/call`).
2. **Подключить.** Apps → Connect an app → Connect your own MCP server →
   вставить `http://<host>:<port>/mcp` → **Check link**. Выбрать
   аутентификацию:
   - без входа — сервис открыт в сети;
   - ключ или токен — уходит заголовком `Authorization: Bearer …`;
   - кастомные заголовки — если сервис требует свои имена;
   - расширенная вставка — если README сервиса содержит сниппет
     `mcpServers` (кастомные имена заголовков выживают через этот путь).
   Каждое введённое значение становится секретом компании; обратно
   показываются только имена заголовков.
3. **Ревью каталога.** Найденные действия перечислены; чтения можно включить
   для ревью, меняющие действия по умолчанию выключены, вновь найденные
   карантинятся до разбора. Включить ровно те действия, что нужны агентам.
4. **Выдать агентам.** В выборе доступа указать агентов (по агенту) или всю
   компанию. Профиль по умолчанию `deny` с явными включениями —
   неперечисленный агент не видит ничего. Править позже: Apps → Advanced →
   Profiles или в карточке агента, секция инструментов.
5. **Проверить из прогона.** Разбудить агента с грантом и попросить
   перечислить MCP-инструменты; новые приходят как
   `mcp.<имя-подключения>…:<инструмент>`. Вызов от агента без гранта
   отклоняется `deny_default`.
6. **Здоровье.** Карточка подключения показывает статус и сообщение;
   упавший сервис переводит карточку в «требует внимания», но — по строке
   форка P9 — сбой одного инструмента не прячет остальные инструменты
   подключения, а медленный вызов не помечает подключение мёртвым.

## Ротация секретов

Ротация креды — переввод значения на подключении (reconnect): новое
значение становится новой версией секрета, старая перестаёт
использоваться. Ротация выданной владельцем сессии (cookie-джар) — забота
коннектора: сервис коннектора записывает обновлённое значение обратно через
REST API ротации секретов доски; подключение продолжает указывать на то же
имя секрета, рутинные обновления действий на доске не требуют.

## Что проверить этому деплою перед боем

- Env доски: `PAPERCLIP_DEPLOYMENT_MODE=authenticated`,
  `PAPERCLIP_DEPLOYMENT_EXPOSURE=private` — приватные эндпоинты принимаются.
  Не переключать exposure в `public`, пока подключён приватный коннектор,
  иначе каждый вызов упрётся в гвард.
- Контейнер MCP-сервиса — в сети, доступной серверу доски, и его имя
  резолвится из процесса доски (гвард резолвит и пинит DNS до набора
  номера).
- Креды живут в секретном хранилище компании, не в compose-файлах.
