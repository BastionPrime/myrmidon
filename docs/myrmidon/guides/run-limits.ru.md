# Лимиты допуска прогонов

> English version: [run-limits.md](run-limits.md)

Сервер может ограничивать, сколько прогонов побудок он запускает одновременно,
как быстро он их стартует и сколько свободной памяти он держит в запасе. С выпуска
1.3 эти лимиты меняются на лету: из интерфейса или через API, без перезапуска
сервера и без обрыва уже идущих прогонов.

## Четыре лимита

| Настройка | Что ограничивает | По умолчанию |
|---|---|---|
| `maxConcurrentRuns` | Сколько прогонов этот процесс сервера держит в работе одновременно. Прогоны сверх потолка остаются `queued`; очередь идёт от старых к новым | выключено |
| `maxStartsPerMinute` | Сколько прогонов может стартовать за скользящую минуту | выключено |
| `minFreeMemoryMb` | Прогон стартует, только если после его бюджетирования в cgroup сервера (v2) останется столько свободной памяти | выключено |
| `runMemoryEstimateMb` | Сколько мегабайт бюджетируется на один прогон при подсчёте свободной памяти | `300` |

Значение «выключено» (пустое поле, `null` в сохранённых настройках) снимает этот
лимит. `runMemoryEstimateMb` выключить нельзя: это бюджет, по которому считается
проверка свободной памяти.

## Откуда берётся действующее значение

У каждого лимита есть один из трёх источников; он показан рядом с полем в
интерфейсе и в ответе API:

- `settings` — значение, сохранённое в настройках инстанса;
- `env` — переменная окружения, значение по умолчанию при первом старте;
- `default` — встроенное значение (только у `runMemoryEstimateMb`: 300 МБ).

Переменные окружения — `MYRMIDON_MAX_CONCURRENT_RUNS`,
`MYRMIDON_MAX_RUN_STARTS_PER_MINUTE`, `MYRMIDON_MIN_FREE_MEMORY_MB` и
`MYRMIDON_RUN_MEMORY_ESTIMATE_MB` (см. [SETTINGS.md](../SETTINGS.md)). Это значения
по умолчанию при первом старте: после того, как лимиты сохранены из интерфейса или
через API, действуют сохранённые настройки, и переменные больше не применяются.

## Изменение лимитов из интерфейса

Откройте Instance → General и найдите секцию «Run limits». Четыре поля показывают
действующие значения и их источники:

- **Concurrent runs**, **Starts per minute**, **Free memory to keep, MB** —
  введите целое число больше нуля или оставьте поле пустым, чтобы выключить лимит
  («No limit»).
- **Memory per run, MB** — бюджет на один прогон; поле обязательно, очистить его
  нельзя.

Нажмите «Save run limits». Нецелое или неположительное значение блокирует
сохранение.

## Изменение лимитов через API

Прочитать действующие лимиты и их источники (любой член организации доски):

```sh
curl -H "Authorization: Bearer <token>" http://localhost:3100/api/myrmidon/runtime-limits
```

Записать новые лимиты (только администратор инстанса). Передавайте только меняемые
ключи; ключ со значением `null` выключает этот лимит:

```sh
curl -X PATCH \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"maxConcurrentRuns": 8, "minFreeMemoryMb": 2048}' \
  http://localhost:3100/api/myrmidon/runtime-limits
```

`0`, отрицательное, дробное или нечисловое значение, `null` у бюджета памяти или
лишний ключ отклоняются с `400`, и ничего не записывается.

## Что происходит после изменения

Изменение сохраняется в `instance_settings.general.runLimits`, в журнал активности
каждой компании пишется запись `instance.runtime_limits.updated` со старыми и новыми
значениями, и только после этого новые лимиты применяются к живому допуску. Подъём
лимита также назначает проход очереди, так что задержанные старым потолком прогоны
стартует в пределах минуты — без перезапуска сервера и без обрыва идущих прогонов.
Понижение лимита тоже не останавливает идущие прогоны; оно лишь задерживает новые
старты, пока счёт не опустится ниже нового потолка.

При старте сервера сохранённые лимиты читаются и применяются до запуска
планировщика.

## Когда проверка памяти не действует

Если процесс не видит предел памяти своего cgroup (`memory.max` равен `max`, на
хосте cgroup v1 или сервер не в контейнере), проверка свободной памяти неактивна, и
один раз в журнал пишется предупреждение `run admission cannot read the cgroup
memory limit…`. Потолки одновременных прогонов и стартов в минуту при этом
действуют. Если предупреждение есть, а предел контейнера задан, — проверьте, как
запущен сервер.
