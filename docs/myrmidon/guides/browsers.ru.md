# Браузеры: экран живого браузера

> English version: [browsers.md](browsers.md)

«Браузеры» — раздел настроек (Настройки → Browsers, маршрут
`company/settings/browsers`, последний пункт панели вкладок настроек), который
позволяет владельцу смотреть и вести живые браузеры, через которые авторизуются
боты: открыть сессию экрана, поддерживать её, закрыть, очистить данные сайта и
прочитать журнал сессий. Пока сессия экрана открыта, боты этот браузер не ведут.

Сама экранная нода (x11vnc + websockify поверх живого браузера) — отдельное
развёртывание; доска держит реестр, таймеры сессий, паузу ботов и журнал, а с
нодой говорит через небольшой HTTP API. Вид noVNC-экрана внутри панели приходит
с экранной нодой (часть B фичи); раздел уже сейчас ведёт полный жизненный цикл
сессии.

## Доступность

Раздел читает реестр из `MYRMIDON_BROWSER_FLEET` на каждый запрос — оператор
меняет переменную, и следующая загрузка страницы показывает новый список;
перезапуск сверх применения окружения не нужен. Когда переменная не задана,
страница показывает «No browsers are configured on this instance.» Неверное
значение (битый JSON, не-массив, плохой или повторный id, слишком много записей
или ключей egress) читается как пустой реестр с предупреждением в журнале
сервера — страница отвечает пустым списком, а не ошибкой.

Сессии экрана дополнительно требуют адрес и токен экранной ноды
(`MYRMIDON_BROWSER_CONSOLE_HOST`, `MYRMIDON_BROWSER_CONSOLE_TOKEN`). Без них
«Open screen» завершается ошибкой «The screen node did not answer» (HTTP 502).

## Кто что может

- Любой аутентифицированный пользователь панели читает реестр (список
  браузеров и кто ими пользуется). Агенты тоже могут читать реестр.
- Только владелец — пользователь панели с активной ролью owner в компании,
  администратор инстанса или local implicit — открывает и закрывает сессии
  экрана, чистит данные сайта и читает журнал. Агентам на всё это — 403.
- Heartbeat и Done принимаются только от владельца, открывшего сессию; другой
  владелец получает 403, пока сессия открыта.

## Список браузеров

Каждый настроенный браузер — карточка с отображаемым именем, id и метками
маршрутов egress, взятая из `MYRMIDON_BROWSER_FLEET` (JSON-массив:

```json
[{"id":"browser-a","displayName":"Live browser A","egress":{"ru":"socks ru1","ig":"socks nd1"}}]
```

Идентификаторы — строчные слаги; не больше 16 браузеров и не больше 8 ключей
egress на браузер. Пока на браузере открыта сессия экрана, карточка показывает
«In use by <id пользователя>»; список обновляется сам каждые 15 секунд.

## Открытие сессии экрана

Нажмите **Open screen** на карточке браузера. Доска вызывает экранную ноду,
просит её приостановить ботов на этом браузере и записывает сессию. Если сессия
на этом браузере уже открыта, вызов отвечает 409; если нода не ответила или не
смогла приостановить ботов, вызов отвечает 502, и ничего не остаётся
полуоткрытым.

Пока сессия открыта, на карточке появляется панель экрана с:

- обратным отсчётом автозакрытия («Auto-close in …»), который ведут два
  таймера — таймаут простоя (`MYRMIDON_BROWSER_IDLE_TIMEOUT_MIN`, по умолчанию
  30 минут без сообщённой активности) и жёсткий потолок
  (`MYRMIDON_BROWSER_MAX_DURATION_MIN`, по умолчанию 120 минут независимо от
  активности). Сессия закрывается по тому дедлайну, что наступит раньше;
- предупреждением об автозакрытии в последние 60 секунд перед дедлайном;
- кнопкой **Report activity**, которая сбрасывает таймер простоя (вид экрана
  части B сообщает активность мыши и клавиш тем же способом; пустой keep-alive
  heartbeat каждые 30 секунд его не сбрасывает);
- кнопкой **Done**, которая закрывает сессию и возобновляет ботов.

Сессия переживает перезагрузку страницы и делится между вкладками: повторно
открытая страница подхватывает открытую сессию. Закрытие работает из любой
вкладки владельца, но сессия, открытая другим владельцем, отвечает 403 на
heartbeat и Done.

## Пауза ботов, пока экран открыт

Два независимых контура держат ботов вне браузера на время сессии:

1. Контракт экранной ноды: нода получает вызов `pause` для браузера при
   открытии сессии и `resume` при её закрытии, как бы она ни закрылась — Done,
   таймаут простоя или жёсткий потолок.
2. Серверная страховка MCP: доска регистрирует сторож, который отклоняет
   MCP-вызовы инструментов, нацеленные на этот браузер, с HTTP 423 («An owner
   screen session is open on this browser; MCP calls are paused»), пока сессия
   жива. Страховка держится, даже если вызов ноды потерян. В этой части фичи
   сторож зарегистрирован и покрыт тестами; шлюз инструментов начнёт
   обращаться к нему в точках вызова браузерных инструментов с частью B.

## Закрытие и журнал

Сессия завершается одним из трёх способов, и каждый записывается в журнал:

| Кем закрыта | Значение |
|---|---|
| `done` | Владелец нажал Done |
| `idle_timeout` | Не было активности в течение таймаута простоя |
| `max_duration` | Сработал жёсткий потолок, даже при постоянной активности |

Журнал (раздел Session journal под списком) хранит последние 50 сессий по всем
браузерам: id браузера, кто открыл, время начала, длительность и причину
закрытия. Сессии и журнал живут в
`instance_settings.general.myrmidonBrowserConsole` — миграций базы нет, и ключ
переживает вендорские записи общих настроек.

## Очистка данных сайта

На каждой карточке есть форма Clear site data: введите голый домен
(`example.com`, никогда URL) и подтвердите. Нода очищает cookies и storage этого
домена в живом браузере через CDP. Форма отказывается работать, пока на этом
браузере открыта сессия экрана (409) — сначала закройте экран. Недоступная нода
отвечает 502.

## Поверхность API

Базовый путь `/api/myrmidon/browsers`; все вызовы, кроме списка реестра,
принимают `companyId` query-параметром:

```text
GET    /api/myrmidon/browsers                      — реестр + состояние живых сессий
POST   /api/myrmidon/browsers/:id/screen/open      — открыть сессию (владелец)
POST   /api/myrmidon/browsers/:id/screen/heartbeat — keep-alive / сообщить активность (владелец сессии)
POST   /api/myrmidon/browsers/:id/screen/done      — закрыть сессию (владелец сессии)
DELETE /api/myrmidon/browsers/:id/data             — очистить данные сайта, тело {"domain":"example.com"} (владелец)
GET    /api/myrmidon/browsers/journal              — последние 50 сессий (владелец)
```

## Настройки

Все пять переменных описаны в [../SETTINGS.ru.md](../SETTINGS.ru.md), раздел
«1.4 — экран живого браузера (BROWSER-CONSOLE)»: `MYRMIDON_BROWSER_FLEET`,
`MYRMIDON_BROWSER_CONSOLE_HOST`, `MYRMIDON_BROWSER_CONSOLE_TOKEN`,
`MYRMIDON_BROWSER_IDLE_TIMEOUT_MIN`, `MYRMIDON_BROWSER_MAX_DURATION_MIN`.

## Заметки оператора

- Строка доски — BROWSER-CONSOLE в [../DIVERGENCE.md](../DIVERGENCE.md); модуль —
  `server/src/myrmidon/browser-console/`, UI —
  `ui/src/components/myrmidon/browsers/`, маршрут смонтирован в
  `server/src/app.ts` и `ui/src/App.tsx`.
- Значения хоста и токена никогда не логируются.
- Очистка данных сайта необратима для cookies и storage этого домена в живом
  браузере — авторизации на этом сайте теряются.
