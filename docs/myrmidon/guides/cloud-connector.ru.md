# Облака: облачное хранилище через коннектор

> English version: [cloud-connector.md](cloud-connector.md)

Коннектор облаков (CLOUD-CONNECTOR, выпуск 1.4) делает облачное хранилище
штатным модулем доски: владелец один раз подключает облачный аккаунт на
провайдера из панели, и доступ к папкам раздаётся агентам оттуда же. Токен
OAuth живёт в хранилище секретов инстанса как секрет компании — боты и агенты
его не видят.

Модуль — `server/src/myrmidon/cloud-connector/`; контракт —
`packages/shared/src/myrmidon-cloud-connector.ts`; экран владельца —
Настройки → Clouds (`company/settings/clouds`).

## Как это устроено

- **Аккаунты.** Один подключённый аккаунт на провайдера в пределах компании.
  Владелец подключает из Настройки → Clouds: кнопка **Connect** запускает
  OAuth (`POST /api/myrmidon/cloud-connector/oauth/:providerId/start` отдаёт
  адрес авторизации провайдера с одноразовым state, с PKCE там, где провайдер
  его поддерживает), провайдер возвращает владельца на
  `GET /api/myrmidon/cloud-connector/oauth/callback`, и токен-набор
  (access + refresh + срок) записывается секретом компании с именем
  `myrmidon-cloud-<provider>` в хранилище секретов инстанса. В состоянии
  коннектора остаётся только id секрета — значение токена через API доски не
  проходит. Перед вызовом провайдера access-токен обновляется автоматически,
  если до истечения осталось меньше 60 секунд (`CLOUD_TOKEN_REFRESH_SKEW_MS`),
  с дедупликацией параллельных обновлений одного аккаунта и записью нового
  набора под проверкой версии. Папка, у чьей компании нет подключённого
  аккаунта, отвечает на облачный вызов `409 not connected`.
- **Корни.** Корень — папка, до которой дотягивается аккаунт коннектора, со
  стабильным slug в нижнем регистре (`[a-z0-9-]`, уникален в пределах
  провайдера): его видит владелец и его же называет агент. Два вида: `own` —
  путь к папке в диске аккаунта; `shared` — папка, которую нам расшарил другой
  аккаунт, адресуется парой drive id + item id и для нас всегда только на
  чтение. У Яндекс Диска адресации общего диска нет, поэтому `shared`-корень
  на Яндексе отклоняется с «заведи папку как own».
- **Доступы (grants).** Владелец раздаёт корень агенту, касте или всем
  (`all`) с режимом `ro` (чтение) или `rw` (чтение-запись). Один доступ на
  пару (корень, адресат): повторная выдача заменяет режим. Если агенту
  подходят несколько доступов, побеждает самый конкретный (`agent` сильнее
  `caste`, `caste` сильнее `all`); при равной конкретности побеждает `rw`.
  Доступ по касте совпадает с ролью агента на доске (`agents.role`), читаемой
  на каждый вызов, — агент с пустой ролью касты не имеет и совпадает только с
  доступами «этому агенту» и «всем».
- **Личная папка.** Имя корня `personal` зарезервировано
  (`CLOUD_PERSONAL_ROOT_ALIAS`): оно всегда означает собственную папку
  вызвавшего агента. При первом обращении коннектор создаёт её
  (`Agents/<agent id>` в диске аккаунта, имя корня `agent-<agent id>`) и
  выдаёт в `rw` только этому агенту. Владелец не может завести корень с именем
  `personal` (`400 reserved`). Алиас разрешается в то единственное облако,
  которое подключено у компании агента; при отсутствии подключённого
  аккаунта, при неизвестной компании или при нескольких подключённых облаках
  агент получает отказ `409`, называющий провайдеров и просящий владельца
  указать, какая папка его.

## Кто что может

- Настройка (аккаунты, корни, доступы, дерево папок, журнал) — только
  владельцу: пользователю доски с активной ролью owner в компании, админу
  инстанса или локальному implicit-актору. Агенты на всё это получают 403;
  неаутентифицированные вызовы — 401.
- Агенту доступны три вещи: список своих выданных корней
  (`GET /api/myrmidon/cloud-connector/roots` возвращает агенту только его
  срез), точка вызова инструментов
  `POST /api/myrmidon/cloud-connector/call` и MCP-поверхность
  `POST /api/mcp/cloud-tools`.
- Обе агентские точки строят личность вызывающего одинаково (`identity.ts`):
  id агента, его компания и его роль на доске как метка касты — поэтому две
  поверхности не могут разойтись в том, кто вызывает и какие доступы
  применяются.

## Инструменты агента

Шесть инструментов (`CLOUD_TOOL_NAMES`), доступные двумя путями через один
сервис — поэтому доступы, конфайнмент пути и журнал применяются одинаково:

- `POST /api/myrmidon/cloud-connector/call` с телом `{tool, root, ...}`;
- MCP-эндпоинт `POST /api/mcp/cloud-tools` (JSON-RPC: `initialize`,
  `notifications/initialized`, `tools/list`, `tools/call`). Описание аргумента
  `root` в `tools/list` сообщает агенту про зарезервированное имя `personal`.
  Пользователь доски и аноним получают там 401; отказ приходит как ошибка
  инструмента с названной границей.

| Инструмент | Что делает |
|---|---|
| `cloud_list` | Список содержимого папки внутри корня (до 200 записей; `truncated: true`, когда записей больше). |
| `cloud_search` | Поиск внутри корня по запросу (1–200 символов, без кавычек и обратной косой; до 20 попаданий). Попадание возвращается, только если доказуемо лежит внутри корня. У Яндекс Диска поискового API нет, поэтому там `search` обходит выданный корень (с ограничением глубины и числа записей) — попадание вне корня невозможно по построению. |
| `cloud_read` | Читает файл в память как base64; потолок — 200 000 байт (`CLOUD_READ_LIMIT_BYTES`). Больший файл отклоняется с «use download». |
| `cloud_download` | Читает файл как base64 с потолком 64 МиБ (`CLOUD_DOWNLOAD_LIMIT_BYTES`). |
| `cloud_upload` | Пишет base64-содержимое по пути (нужен `rw`). Отсутствующие родительские папки создаются. Существующее имя + `overwrite: false` → 409. Маленькие файлы уходят одним запросом; большие — сессией кусками (resumable). |
| `cloud_move` | Перемещает/переименовывает в пределах одного провайдера (нужен `rw` на обоих корнях — источника и назначения). Существующее назначение → 409. Переход между провайдерами отклоняется («not supported»). |

### Адресация: корень + путь, никогда id элемента

Агент адресует ровно пару — slug корня (или `personal`) и путь внутри него.
Коннектор разрешает путь через провайдера; id элементов провайдера от
вызывающего не принимаются. Правила путей
(`server/src/myrmidon/cloud-connector/paths.ts`):

- разделители нормализуются (`\` → `/`), пустые и `.`-сегменты отбрасываются,
  имена сравниваются в NFC-нормализации без учёта регистра;
- `..` отклоняется; отклоняются символы, запрещённые провайдером, — `"`, `*`,
  `:`, `<`, `>`, `?`, `|`, `\` и управляющие символы; отклоняются сегмент
  длиннее 255 символов и путь глубже 32 сегментов;
- всё разрешается внутри названного корня — адресовать соседа или родителя
  корня невозможно.

### Что значит отказ

Каждый отказ называет границу, на которую натолкнулся вызывающий, а не
внутренности:

- `no access to folder "<корень>": it is not granted to this agent` — корень
  вам не выдан (403). Попросите владельца выдать доступ.
- `folder "<корень>" is granted read-only; writing is not allowed` — у вас
  `ro`; `cloud_upload`/`cloud_move` отклоняются (403).
- `the OneDrive account is not connected; the owner must connect it first`
  (409) — у компании нет подключённого аккаунта этого провайдера; это
  действие со стороны владельца, а не ошибка агента.
- `"personal" is not available yet: no cloud account is connected for this
  company…` / `"personal" is ambiguous here: this company has accounts for
  <провайдеры>…` (409) — зарезервированный алиас не смог разрешиться;
  используйте имя папки, которое дал владелец.
- Сбои провайдера приходят как 403/404/409/502 с коротким сообщением; сырой
  тип ошибки провайдера до вызывающего не доходит.

## Журнал

Каждый вызов инструмента, дошедший до исполнителя, — разрешённый или
отказанный — добавляет одну запись в журнал: время, актор (id вызвавшего
агента), инструмент, id и имя корня, путь, флаг ok и короткая деталь
(`listed N entries`, `read name (B bytes)` или текст отказа). Содержимое
файлов в журнал не попадает. Журнал хранит последние 200 записей; владелец
читает его через `GET /api/myrmidon/cloud-connector/journal` (по умолчанию
100, не более 200). Удаление корня снимает его доступы, но журнал сохраняет.

## Состояние, настройки, эксплуатация

- Состояние коннектора (аккаунты, корни, доступы, журнал) живёт одним
  JSON-документом в `instance_settings.general.myrmidonCloudConnector` — без
  миграции базы. Токен владельца там не живёт: это секрет компании в хранилище
  секретов инстанса (`myrmidon-cloud-<provider>`), записанный потоком
  подключения и ротируемый при каждом автоматическом обновлении. Аккаунты и
  корни привязаны к компании владельца, и провайдер получает токен той
  компании, которой принадлежит корень. Записи идут по схеме
  «прочитал-изменил-записал» под блокировкой строки; записи вендора в general
  сохраняют наш ключ (`preserveCloudConnectorGeneralKey` в
  `server/src/services/instance-settings.ts`).
- Переменные окружения (см. [../SETTINGS.md](../SETTINGS.md), раздел
  «CLOUD-CONNECTOR»): `MYRMIDON_CLOUD_CONNECTOR_REDIRECT_BASE` (публичный
  базовый адрес панели, на который провайдеры возвращают владельца, — без него
  старт подключения отвечает `409`) и на каждого провайдера
  `MYRMIDON_CLOUD_<PROVIDER>_CLIENT_ID` / `MYRMIDON_CLOUD_<PROVIDER>_CLIENT_SECRET`
  (`ONEDRIVE`, `GOOGLE_DRIVE`, `YANDEX_DISK`) — без пары этот провайдер
  подключить нельзя, остальное продолжает работать.
- Все три провайдера зарегистрированы по умолчанию (`index.ts`): OneDrive
  (Microsoft Graph), Google Drive (Drive API v3), Яндекс Диск (REST v1).
  Добавить облако — значит реализовать интерфейс `CloudProvider` и
  зарегистрировать его, без правок ядра.
- Когда подключение не удаётся или доступ отказан, проверяйте по порядку:
  провайдер настроен (`MYRMIDON_CLOUD_<PROVIDER>_CLIENT_ID` задан) и задан
  `MYRMIDON_CLOUD_CONNECTOR_REDIRECT_BASE`; аккаунт подключён (`409` говорит,
  что нет); slug корня написан так, как его завёл владелец; у агента есть
  доступ на этот корень; режим допускает операцию (корни `ro` отклоняют
  запись); в журнале виден отказ с названной границей.

## Экран «Облака»

Настройки → Clouds (`company/settings/clouds`), только для владельца. Экран
показывает подключённые аккаунты (с действием **Connect** на каждого
провайдера), корни с их видом (`in the connected account`,
`shared with us (read only)`), доступы (агент / каста / все, `ro`/`rw`) и
журнал. Дерева папок на экране нет: владельческий маршрут дерева существует,
но экран его не вызывает — агенты перечисляют папки инструментом
`cloud_list`. Экран ходит только в владельческий API выше;
значение токена не показывается никогда.

## Ограничения

- Папка, расшаренная аккаунту коннектора другим аккаунтом, — только чтение по
  построению: доступ `rw` на `shared`-корень отклоняется при записи и
  игнорируется при разрешении.
- Ярлыки облака (OneDrive `remoteItem`, Google
  `application/vnd.google-apps.shortcut`) не разыменовываются — такая запись
  отклоняется как «a shortcut to another location».
- Переход между облачными провайдерами не поддерживается.
- Google-native документы (Docs/Sheets/Slides) не скачиваются — отказ просит
  скачать экспортированную копию.
- У Яндекс Диска нет адресации общего диска (`shared`-корень отклоняется) и
  нет поискового эндпоинта (`search` вместо этого обходит выданный корень).
- Один подключённый аккаунт на провайдера в пределах компании:
  переподключение заменяет прежнюю запись аккаунта.
- Загрузки, скачивания и чтения ограничены (чтение 200 000 байт, скачивание
  64 МиБ, 6 000 000 символов base64 на вызов).

## Поверхность API

Базовые пути `/api/myrmidon/cloud-connector` (настройка владельцем и вызов
агента) и `/api/mcp/cloud-tools` (MCP агента). Настроечные вызовы принимают
`companyId` query-параметром:

```text
GET    /api/myrmidon/cloud-connector/accounts              — владелец
POST   /api/myrmidon/cloud-connector/oauth/:providerId/start — владелец (отдаёт адрес авторизации провайдера)
GET    /api/myrmidon/cloud-connector/oauth/callback        — доска (одноразовый state)
DELETE /api/myrmidon/cloud-connector/accounts/:id          — владелец
GET    /api/myrmidon/cloud-connector/roots                 — владелец; агент получает свой срез
POST   /api/myrmidon/cloud-connector/roots                 — владелец
DELETE /api/myrmidon/cloud-connector/roots/:id             — владелец
GET    /api/myrmidon/cloud-connector/grants                — владелец
PUT    /api/myrmidon/cloud-connector/grants                — владелец
DELETE /api/myrmidon/cloud-connector/grants/:id            — владелец
GET    /api/myrmidon/cloud-connector/tree                  — владелец (дерево папок одного корня)
GET    /api/myrmidon/cloud-connector/journal               — владелец
POST   /api/myrmidon/cloud-connector/call                  — вызов инструмента агентом (в рамках доступа)
POST   /api/mcp/cloud-tools                                — MCP агента (JSON-RPC)
```

## Заметки оператора

- Строки реестра отличий — CLOUD-CONNECTOR, CLOUD-CONNECTOR-B,
  CLOUD-CONNECTOR-C, CLOUD-CONNECTOR-MCP, CLOUD-CONNECTOR-IDENTITY и
  CLOUD-CONNECTOR-UI в
  [../DIVERGENCE.md](../DIVERGENCE.md); модуль —
  `server/src/myrmidon/cloud-connector/`, подключён в `server/src/app.ts`;
  экран — `ui/src/components/myrmidon/clouds/`.
- Приёмочное поведение покрыто `*.myrmidon.test.ts` рядом с модулем: модель
  доступа, конфайнмент путей, авторизация маршрутов, OAuth-поток (адрес
  авторизации, PKCE, обмен кода, одноразовый state), хранилище токенов и
  обновление (запас 60 секунд, дедупликация, проверка версии),
  MCP-поверхность и каждый провайдер (адресация, ярлыки, конфайнмент поиска,
  маппинг ошибок).
- Модуль заменяет временную службу `tools/cloud-files` (см.
  [cloud-files-connector.md](cloud-files-connector.md)); правила путей
  перенесены так, что доска принимает ровно те пути, которые принимала та
  служба.
