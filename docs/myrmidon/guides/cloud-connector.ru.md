# Облака: облачное хранилище через коннектор

> English version: [cloud-connector.md](cloud-connector.md)

Коннектор облаков (CLOUD-CONNECTOR, выпуск 1.4) делает облачное хранилище
штатным модулем доски: владелец один раз подключает облачный аккаунт на
провайдера, а доступ к папкам раздаётся агентам с доски. Токен доступа хранит
коннектор — боты и агенты его не видят.

Руководство описывает, что делает код. Где часть относится к более поздней
части фичи (часть B: подключение по OAuth и экран «Облака»; часть C:
провайдеры Google Drive и Яндекс Диск), это отмечено явно. Сам модуль —
`server/src/myrmidon/cloud-connector/`; контракт —
`packages/shared/src/myrmidon-cloud-connector.ts`.

## Как это устроено

- **Аккаунты.** Один подключённый аккаунт на провайдера. Повторное подключение
  того же провайдера заменяет прежнюю запись аккаунта. В записи хранится
  `tokenRef` — имя секрета коннектора с refresh-токеном, — а не сам токен.
  Пока в боевой сборке не подключён резолвер токена, любой вызов провайдера
  отвечает `409` («the account is not connected; the owner must connect it
  first»).
- **Корни.** Корень — папка, до которой дотягивается аккаунт коннектора, со
  стабильным slug в нижнем регистре (`[a-z0-9-]`, уникален в пределах
  провайдера): его видит владелец и его же называет агент. Два вида: `own` —
  путь к папке в диске аккаунта; `shared` — папка, которую нам расшарил другой
  аккаунт, адресуется парой drive id + item id и для нас всегда только на
  чтение.
- **Доступы (grants).** Владелец раздаёт корень агенту, касте или всем
  (`all`) с режимом `ro` (чтение) или `rw` (чтение-запись). Один доступ на
  пару (корень, адресат): повторная выдача заменяет режим. Если агенту
  подходят несколько доступов, побеждает самый конкретный (`agent` сильнее
  `caste`, `caste` сильнее `all`); при равной конкретности побеждает `rw`.
- **Личная папка.** Каждый агент получает личный корень автоматически при
  первом обращении: имя — `agent-<agent id>`, папка — `Agents/<agent id>` в
  диске аккаунта, создаётся при отсутствии и выдаётся в `rw` только этому
  агенту.

## Кто что может

- Настройка (аккаунты, корни, доступы, дерево папок, журнал) — только
  владельцу: пользователю доски с активной ролью owner в компании, админу
  инстанса или локальному implicit-актору. Агенты на всё это получают 403;
  неаутентифицированные вызовы — 401.
- Агенту доступны ровно две вещи: список своих выданных корней
  (`GET /api/myrmidon/cloud-connector/roots` возвращает агенту только его
  срез) и точка вызова инструментов
  `POST /api/myrmidon/cloud-connector/call`.
- Доступы вида `caste` хранятся и разрешаются моделью доступа, но текущий
  маршрут вызова инструментов строит личность агента с `caste: null`, поэтому
  доступ по касте пока не срабатывает на вызове инструмента; сопоставление
  касты достраивается в части B (агентский инструментальный контур).

## Инструменты агента

Контракт определяет шесть инструментов (`CLOUD_TOOL_NAMES`); в части A они
выполняются через `POST /api/myrmidon/cloud-connector/call` с телом
`{tool, root, ...}`. Выставление их как MCP-инструментов через шлюз
инструментов — часть B.

| Инструмент | Что делает |
|---|---|
| `cloud_list` | Список содержимого папки внутри корня (до 200 записей; `truncated: true`, когда записей больше). |
| `cloud_search` | Поиск внутри корня по запросу (1–200 символов, без кавычек и обратной косой; до 20 попаданий). Попадание возвращается, только если доказуемо лежит внутри корня, — провайдер поднимается по родителям и отбрасывает всё, что не подтверждено. |
| `cloud_read` | Читает файл в память как base64; потолок — 200 000 байт (`CLOUD_READ_LIMIT_BYTES`). Больший файл отклоняется с «use download». |
| `cloud_download` | Читает файл как base64 с потолком 64 МиБ (`CLOUD_DOWNLOAD_LIMIT_BYTES`). |
| `cloud_upload` | Пишет base64-содержимое по пути (нужен `rw`). Отсутствующие родительские папки создаются. Существующее имя + `overwrite: false` → 409. Маленькие файлы уходят одним запросом; большие — сессией кусками. |
| `cloud_move` | Перемещает/переименовывает в пределах одного провайдера (нужен `rw` на обоих корнях — источника и назначения). Существующее назначение → 409. Переход между провайдерами отклоняется («not supported»). |

### Адресация: корень + путь, никогда id элемента

Агент адресует ровно пару — slug корня и путь внутри него. Коннектор разрешает
путь через провайдера; id элементов провайдера от вызывающего не принимаются.
Правила путей (`server/src/myrmidon/cloud-connector/paths.ts`):

- разделители нормализуются (`\` → `/`), пустые и `.`-сегменты отбрасываются,
  имена сравниваются в NFC-нормализации без учёта регистра;
- `..` отклоняется; отклоняются символы, запрещённые провайдером, — `"`, `*`,
  `:`, `<`, `>`, `?`, `|`, `\` и управляющие символы; отклоняются сегмент
  длиннее 255 символов и путь глубже 32 сегментов;
- всё разрешается внутри названного корня — адресовать соседа или родителя
  корня невозможно.

### Что значит отказ

Каждый отказ называет границу, на которую натолкнулся вызывающий, а не
внутренности:

- `no access to folder "<корень>": it is not granted to this agent` — корень
  вам не выдан (403). Попросите владельца выдать доступ; в сообщении — slug
  корня, который вы передали.
- `folder "<корень>" is granted read-only; writing is not allowed` — у вас
  `ro`; `cloud_upload`/`cloud_move` отклоняются (403).
- `the OneDrive account is not connected; the owner must connect it first`
  (409) — нет резолвера токена; это действие со стороны владельца, а не
  ошибка агента.
- Сбои провайдера приходят как 403/404/409/502 с коротким сообщением; сырой
  тип ошибки провайдера до вызывающего не доходит.

## Журнал

Каждый вызов инструмента — разрешённый или отказанный — добавляет одну запись
в журнал: время, актор (id агента, а для действий владельца — id пользователя
доски), инструмент, id и имя корня, путь, флаг ok и короткая деталь
(`listed N entries`, `read name (B bytes)` или текст отказа). Содержимое
файлов в журнал не попадает. Журнал хранит последние 200 записей; владелец
читает его через `GET /api/myrmidon/cloud-connector/journal` (по умолчанию
100, не более 200). Удаление корня снимает его доступы, но журнал сохраняет.

## Состояние, настройки, эксплуатация

- Всё состояние (аккаунты, корни, доступы, журнал) живёт одним JSON-документом
  в `instance_settings.general.myrmidonCloudConnector` — без миграции базы;
  старый образ продолжает работать на этой схеме. Записи вендора в general
  сохраняют наш ключ (`preserveCloudConnectorGeneralKey` в
  `server/src/services/instance-settings.ts`). Записи идут по схеме
  «прочитал-изменил-записал» под блокировкой строки.
- В части A **переменных окружения нет** (см.
  [../SETTINGS.md](../SETTINGS.md), раздел «CLOUD-CONNECTOR»). Части B и C
  добавят свои туда же.
- Провайдеры — реестр (`CloudProviderRegistry`): провайдер OneDrive
  (Microsoft Graph) зарегистрирован в части A; Google Drive и Яндекс Диск
  регистрируются так же в части C, без правок ядра.
- Когда подключение не удаётся или доступ отказан, проверяйте по порядку:
  аккаунт подключён (`409` говорит, что нет); slug корня написан так, как его
  завёл владелец; у агента есть доступ на этот корень (владелец видит доступы
  и журнал тем же API); режим допускает операцию (корни `ro` отклоняют
  запись); в журнале виден отказ с названной границей.

## Ограничения

- Папка, расшаренная аккаунту коннектора другим аккаунтом, — только чтение по
  построению: доступ `rw` на `shared`-корень отклоняется при записи и
  игнорируется при разрешении.
- Ярлыки облака (OneDrive `remoteItem`) не разыменовываются — такая запись
  отклоняется как «a shortcut to another location».
- Переход между облачными провайдерами не поддерживается.
- Один подключённый аккаунт на провайдера: переподключение заменяет прежнюю
  запись аккаунта.
- Загрузки, скачивания и чтения ограничены (чтение 200 000 байт, скачивание
  64 МиБ, 6 000 000 символов base64 на вызов).

## Поверхность API

Базовый путь `/api/myrmidon/cloud-connector`; настроечные вызовы принимают
`companyId` query-параметром:

```text
GET    /api/myrmidon/cloud-connector/accounts        — владелец
POST   /api/myrmidon/cloud-connector/accounts        — владелец
DELETE /api/myrmidon/cloud-connector/accounts/:id    — владелец
GET    /api/myrmidon/cloud-connector/roots           — владелец; агент получает свой срез
POST   /api/myrmidon/cloud-connector/roots           — владелец
DELETE /api/myrmidon/cloud-connector/roots/:id       — владелец
GET    /api/myrmidon/cloud-connector/grants          — владелец
PUT    /api/myrmidon/cloud-connector/grants          — владелец
DELETE /api/myrmidon/cloud-connector/grants/:id      — владелец
GET    /api/myrmidon/cloud-connector/tree            — владелец (дерево папок одного корня)
GET    /api/myrmidon/cloud-connector/journal         — владелец
POST   /api/myrmidon/cloud-connector/call            — вызов инструмента агентом (в рамках доступа)
```

## Заметки оператора

- Строка реестра отличий — CLOUD-CONNECTOR в
  [../DIVERGENCE.md](../DIVERGENCE.md); модуль —
  `server/src/myrmidon/cloud-connector/`, подключён в `server/src/app.ts`.
- Приёмочное поведение покрыто `*.myrmidon.test.ts` рядом с модулем: модель
  доступа, конфайнмент путей, авторизация маршрутов, провайдер OneDrive
  (адресация, ярлыки, конфайнмент поиска, маппинг ошибок) и сценарий сервиса —
  агент читает и пишет свою папку, общую только читает, до чужой не
  дотягивается, и каждый вызов попадает в журнал.
- Модуль заменяет временную службу `tools/cloud-files` (см.
  [cloud-files-connector.md](cloud-files-connector.md)); правила путей
  перенесены так, что доска принимает ровно те пути, которые принимала та
  служба.
