# H1: навыки Hermes в профиле своего агента

Касается агентов с адаптером `hermes_local`. Изменение — в `packages/adapters/hermes/src/server/skills.ts`
и `myrmidon-skills-home.ts` рядом с ним, метка `myrmidon(H1)`.

## Что было

Адаптер ставил ссылки на навыки, которыми управляет доска, в `<HOME>/.hermes/skills`. `HERMES_HOME`
он не читал. Hermes с профилем читает навыки из `<HERMES_HOME>/skills`: профиль изолируется
`HERMES_HOME`, а `HOME` у профилей намеренно общий. Поэтому при общем `HOME` у нескольких агентов:

- навыки попадали в общий каталог, который Hermes этих агентов не читает;
- каждый прогон удалял из общего каталога чужие ссылки: адаптер снимает управляемые ссылки, которых
  нет в наборе текущего агента.

## Что изменилось

- Если в карточке агента (`adapterConfig.env`) задан `HERMES_HOME`, навыки ставятся в
  `<HERMES_HOME>/skills` и перечисляются оттуда же. Удаляются только управляемые ссылки в этом
  каталоге — то есть только ссылки этого агента.
- Без `HERMES_HOME` в карточке всё как у вендора: `<HOME>/.hermes/skills`.
- `HERMES_HOME` берётся только из карточки агента, не из окружения сервера. `~` в начале пути
  раскрывается относительно `HOME` из карточки (или домашнего каталога сервера). Переменные
  вида `$VAR` адаптер не раскрывает, в отличие от Hermes: указывайте путь без них.
- Прогон с временным `HERMES_HOME` (P4, инструменты MCP доски) на это не влияет: навыки ставятся в
  постоянный профиль из карточки, временный каталог ссылается на него.

## Что произойдёт при первом прогоне после обновления

Для агента с `HERMES_HOME` в карточке:

1. Адаптер создаёт `<HERMES_HOME>/skills`, если его нет, и ставит туда ссылки на навыки агента.
2. Если на месте управляемого навыка в профиле лежит **настоящий каталог или файл** (например,
   `skills/paperclip`, скопированный вручную), адаптер переносит его в
   `<HERMES_HOME>/skills.pre-myrmidon/<имя>.pre-myrmidon-<ГГГГММДД>` (при повторе в тот же день —
   с суффиксом `-2`, `-3`…) и ставит ссылку. В журнал прогона пишется одна строка:

   ```text
   [hermes] Moved the profile's own "paperclip" skill to skills.pre-myrmidon/paperclip.pre-myrmidon-20260927 and linked the managed skill.
   ```

   Содержимое не удаляется. Раньше в этом случае прогон не стартовал с ошибкой
   `Cannot start without the required Paperclip-managed skills … occupied by another installation`.
3. Ссылка на **другую живую установку** навыка (символьная ссылка на чужой каталог) не трогается:
   прогон по-прежнему останавливается с `occupied by another installation`. Такую ссылку
   разбирает человек.

Бэкап лежит вне `skills/` намеренно. Hermes находит навыки по каждому `SKILL.md` внутри `skills/`
на любой глубине, имя берёт из поля `name:` во frontmatter, а каталоги с точкой в имени не
пропускает. Копия внутри `skills/` осталась бы вторым навыком с тем же именем (см. ниже).

Для агентов без `HERMES_HOME` в карточке ничего не меняется.

## Старые ссылки в общем `<HOME>/.hermes/skills`

Для агентов с `HERMES_HOME` старые ссылки в общем каталоге безвредны: Hermes этих агентов его не
читает. Но `<HOME>/.hermes` — это профиль по умолчанию. Если хоть один агент (или человек)
работает без `HERMES_HOME`, этот каталог — его рабочий, и чистить его нельзя.

Если профилем по умолчанию никто не пользуется, управляемые ссылки можно убрать. Скрипта очистки
нет. Сначала посмотреть, что будет удалено (только символьные ссылки первого уровня, каталоги не
затрагиваются):

```sh
find "$HOME/.hermes/skills" -mindepth 1 -maxdepth 1 -type l -printf '%f -> %l\n'
```

Затем удалить именно их:

```sh
find "$HOME/.hermes/skills" -mindepth 1 -maxdepth 1 -type l -delete
```

Выполнять от имени пользователя, под которым работает сервер, с его `HOME`.

## Локальные копии навыков в профиле

У Hermes есть правило **Local precedence**: если навык с одним именем есть и в локальном каталоге
профиля (`<HERMES_HOME>/skills`), и во внешнем (`skills.external_dirs` в `config.yaml`), побеждает
локальный. Управляемые навыки доски — тоже в локальном каталоге, поэтому это правило их не
затеняет и не защищает. Если в `<HERMES_HOME>/skills` есть своя копия под другим каталогом, но с
тем же `name:`, что у управляемого навыка:

- в списке навыков, индексе системного промпта и командах `/имя` побеждает та, чей путь раньше по
  алфавиту, без предупреждения;
- чтение навыка по имени (`skill_view`) отказывает с `Ambiguous skill name`, если файлы не
  совпадают байт в байт.

Поэтому не держите в профиле копий управляемых навыков с тем же именем. Нужен свой вариант —
дайте ему другое `name:` во frontmatter. Проверенное поведение — Hermes `NousResearch/hermes-agent`
на 27.09.2026.

## Откат

1. Вернуть предыдущий образ. Адаптер снова ставит навыки в `<HOME>/.hermes/skills`, у агентов с
   профилями возвращается прежняя проблема: навыки не видны и стираются соседями.
2. Ссылки в `<HERMES_HOME>/skills` можно оставить: прежний адаптер их не трогает, Hermes профиля
   продолжит их видеть.
3. Вернуть перенесённую копию навыка, если она нужна (подставьте имя и дату из строки журнала):

   ```sh
   rm "$HERMES_HOME/skills/paperclip"   # это символьная ссылка, не каталог
   mv "$HERMES_HOME/skills.pre-myrmidon/paperclip.pre-myrmidon-20260927" "$HERMES_HOME/skills/paperclip"
   ```

   Прежний адаптер на таком каталоге снова откажется запускать прогон, если навык обязателен.
