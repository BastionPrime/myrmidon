# Дорожная карта Myrmidon

Редакция 27.09.2026, по решениям владельца от 27.09.

**Как читать.** У каждой функции сквозной номер:

- P — паритет с тем, что сейчас работает у нас заплатками;
- R — выпуск и эксплуатация;
- S — безопасность;
- M — модели;
- H — навыки и адаптеры Hermes;
- N — надёжность побудок и прогонов;
- U — удобство;
- X — практики из других продуктов.

Колонка «Трек» — какая сессия делает пункт, задания в [tracks/](tracks/). «Готово, когда» —
критерий приёмки. Проверка — тестом в репозитории, если не сказано иное.

## V1.0 — первый выпуск

**Цель.** Всё, что сейчас держится заплатками поверх образа вендора, переходит в исходники с
тестами. Появляются сборка, выкат и откат. Закрыты быстрые дыры безопасности.

### Паритет

| № | Что даёт | Готово, когда | Трек |
|---|---|---|---|
| P1 | Отмена или пауза прогона освобождает аренду окружения. Зависшие аренды подметаются | Тест: после отмены или паузы аренда освобождена. Активная аренда на завершённом прогоне с мёртвым процессом старше запаса (настройка, по умолчанию 10 мин) переходит в `expired`. Аренду с живым процессом подметание не трогает | 2 |
| P2 | Побудка адресата карточки подтверждения не гасится при смене исполнителя | Тест: побудка `interaction_pending` у адресата, который не исполнитель задачи, доходит до прогона и не отменяется с `issue_assignee_changed` | 2 |
| P3 | Прогон стартует при любой длине истории задачи | Вендорские коммиты #13891 и #13793 перенесены. История продолжения ограничена настройкой (по умолчанию 30 записей), исходный и последний запросы сохраняются. Тест на 500 записях. Промпт Hermes через stdin и проверка размера — в P4 | 2 |
| P4 | Инструменты MCP доски доходят до прогона `hermes_local` | Тесты: серверы из `runtimeMcp` попадают в `config.yaml` прогона, их имена — в `-t`. Промпт идёт через stdin. Размер конверта проверяется до запуска. Временный `HERMES_HOME` удаляется после прогона | 3 |
| P5 | Взять задачу без контекста — понятный ответ 403 до блокировки | Тесты маршрута: 403 до захвата блокировки, в ответе 409 есть `checkoutRunStatus` | 3 |
| P6 | `gh` в прогоне получает учётку через брокер, даже когда публичный адрес сервера из прогона недоступен | Тесты: перебор до 6 кандидатов (10 с на адрес, 60 с всего, повтор на 409). Производные адреса берут протокол слушателя, loopback в списке всегда. Переменные кандидатов переносятся через границу раннера | 3 |
| P7 | Отправитель в Telegram видит, что его вложение не импортировано | Тест: при отброшенном вложении в тред уходит отдельное сообщение с именем файла и причиной (до 3 файлов, остальные — «и ещё N»). Повтор доставки его не дублирует | 4 |
| P7b | Открытие чата агента без ошибки 500 | Вендорский коммит #13654 перенесён вместе с его тестом | 4 |
| P8 | Файлы Telegram до 2 ГБ через свой Bot API | Правка зависимости — через вендорский `patchedDependencies`, без подмены файлов. Предел — настройкой, по умолчанию поведение вендора | 4 |
| P9 | Сбой одного инструмента не отключает подключение MCP целиком | Тесты: таймаут одного `tools/call` не скрывает каталог, сбои вызовов не переключают здоровье подключения. Предохранитель работает на уровне одного инструмента. Подключение не выпадает из набора прогона из-за статуса здоровья. Пороги — настройками | 3 |
| P10 | GET к MCP-шлюзу с `Accept: text/event-stream` получает 405 и `Allow: POST` | Тест обоих GET-обработчиков. Остальной код маршрута — вендорский, без отката | 3 |
| P11 | Пропущенный дамп БД догоняется, пропуск слота виден в `/api/health` | Тесты. Окно — настройкой, по умолчанию выключено | 2 |

### Выпуск и эксплуатация

| № | Что даёт | Готово, когда | Трек |
|---|---|---|---|
| R1 | Репозиторий — продукт: CI, образ, реестр отличий, проверки | CI на каждом PR: typecheck, vitest, сборка. Образ публикуется в `ghcr.io/itkadr-git/myrmidon` с тегом коммита и тегом выпуска. Есть проверка лицензий зависимостей и поиск секретов. Есть тест совместимости плагинов, включая hindsight. [DIVERGENCE.md](DIVERGENCE.md) ведётся | 1 |
| R2 | Еженедельный перенос стабильного релиза вендора | Рутина доски: ветка `sync/<тег>`, слияние тега, тесты, PR с отчётом (что из реестра закрыл вендор, новые workflow, новые миграции). Скрипт покрыт тестами на поддельном апстриме. Токен бота даёт доступ только к `myrmidon` | 5 |
| R3 | Режим обслуживания | Новые прогоны не стартуют. Идущие дожидаются или прерываются с повтором. Рутины и сторожа на паузе. Побудки встают в очередь и доставляются после выхода. В интерфейсе плашка. Выход из режима не оставляет замков. Области действия: инстанс, компания, отдел (руководитель и его подчинённые), агент. API для скриптов выката. Окно обслуживания в Zabbix — встроенная интеграция, по умолчанию выключена. Всё с тестами | 5 |
| R4 | Выкат по отпечатку образа и откат | Скрипты: выкат по digest, дамп перед миграциями, проверка `/api/health` (версия и коммит), откат на предыдущий digest. Описан стенд на отдельной ВМ на копии дампа. Скрипты покрыты тестами | 1 |
| TEL | Телеметрия вендору выключена | По умолчанию ничего не отправляется, адресов вендора в коде нет, включение — только явным адресом. Тест | 1 |
| BR | Минимальный ребрендинг | README и NOTICE Myrmidon. Имена пакетов не меняются | 1 |

### Безопасность

| № | Что даёт | Готово, когда | Трек |
|---|---|---|---|
| S2 | Прогон видит только своё окружение | Окружение локальных адаптеров строится по списку разрешённого. Секреты сервера не наследуются: строка подключения к БД, секрет авторизации, секреты подписи, мастер-ключ секретов. Есть тест «прогон не видит пароль базы» | 6 |
| S4 | Агент не меняет свои настройки, модель проверяется при сохранении | Тесты: `PATCH` своей карточки с токеном агента → 403, неизвестная модель → 422 | 6 |
| S5 | Секреты маскируются в журналах, результатах и сообщениях | Тест: значение известного секрета в выводе прогона, его результате, комментарии и исходящем сообщении чата сохраняется замаскированным | 6 |

### Модели, навыки, адаптеры

| № | Что даёт | Готово, когда | Трек |
|---|---|---|---|
| M1 | Модели в карточке агента: текст, зрение, видео, слух, голос, резервные модели, уровень рассуждений | Поля есть в карточке. Для `hermes_local` они попадают в `config.yaml` конкретного прогона. Пустое поле не меняет профиль. Тесты | 6 |
| H1 | Навыки попадают в профиль своего агента | При заданном `HERMES_HOME` адаптер ставит навыки в `<HERMES_HOME>/skills`. Прогон одного агента не удаляет навыки другого. Конфликт с настоящим каталогом в профиле обработан. Миграция существующих установок описана. Тесты | 4 |
| H4 | Промпт через stdin у всех локальных адаптеров | Тест для каждого адаптера: промпт на 300 КБ не попадает в аргументы процесса | 4 |
| X2 | Режим плана | Вендорский режим `planning` работает с `hermes_local`: указания плана доходят до промпта. Тест. Как включить — в [SETTINGS.md](SETTINGS.md) | 2 |

### Критерии выпуска V1.0

1. Все пункты выше влиты в `main`. У каждого есть строка в [DIVERGENCE.md](DIVERGENCE.md) и
   тест-сторож.
2. CI зелёный, образ собран и помечен тегом выпуска `myr-v1.0.0` (своя версия `1.0.0`).
3. Выпуск проверен на отдельном стенде на копии боевой базы, по `docs/myrmidon/deploy.md`.
4. Боевое развёртывание переведено на образ Myrmidon по digest, заплаток поверх образа не
   осталось.
5. Первый еженедельный перенос вендора прошёл через рутину R2.

Пункты 3–5 выполняет эксплуатация вне облачных сессий.

## 1.1.0 — ближайший выпуск (после 1.0.0 на живой доске, 28.09.2026)

Myrmidon — наш продукт (решение владельца 28.09.2026), Paperclip — только основа. Первым делом
продукт должен называться своим именем.

1. **B1. Бренд Myrmidon вместо Paperclip — везде, где это видит человек.**
   - Интерфейс: заголовок окна и вкладки, логотип в шапке и на входе, favicon и значки
     (`ui/index.html`, `ui/public/*`, `site.webmanifest`), экран «О продукте», пустые экраны,
     подсказки (~640 строк в `ui/src`).
   - Сервер: тексты, которые видит пользователь или агент, — системные комментарии задач
     («Paperclip needs a disposition…», «Paperclip could not resolve…»), письма, сообщения
     в чатах (Telegram), описание в OpenAPI (~340 строк в `server/src`).
   - Одна точка правды: константа имени продукта и каталог ассетов бренда, а не замена
     строк по всему коду. Идентификаторы в коде, API, переменные `PAPERCLIP_*`, имена
     пакетов и таблиц **не** переименовываются: это не видно человеку и ломает совместимость.
   - Атрибуция по лицензии MIT остаётся: в NOTICE и на экране «О продукте» — «основано на
     Paperclip (MIT)».
   - Логотип — от владельца или по его брифу (дизайнер bbq/work), до выпуска — на согласование.
   - Приёмка: поиск по собранному интерфейсу и ответам сервера не находит «Paperclip» в
     видимых текстах, кроме атрибуции; скриншоты входа, шапки, задачи и сообщения в Telegram.
2. **Находки выката 1.0.0 (28.09):**
   - сервер при старте падает на восстановлении прогонов агентов на паузе («Agent is not
     invokable») — 4 перезапуска, прежде чем встать;
   - N1: снимать «не повторять» и у уже закрытых записей разбора
     (`evidence.automaticRecovery.replay=blocked` при `status=resolved`) — сейчас
     `recovery-actions/resolve` отвечает 200 без изменений;
   - выкат: после снятия паузы будить агентов, чьи прогоны оборвала пауза;
   - H3: адаптер `hermes_gateway` не передаёт в прогон секреты из карточки агента
     (`env` с `secret_ref`) — токены разработчиков приходится класть на хост вручную.

## V1.x — еженедельные выпуски после V1.0

По одной-две функции в выпуске, в таком порядке:

1. **S1. Хранилище паролей в интерфейсе.** Секрет привязан к инструменту, подставляет его
   сервер, агент значения не видит, использование записывается в журнал. Внешние хранилища
   (Vault, Vaultwarden, Infisical) подключаются модулями. Основа — вендорские маскировка
   (#9860) и Connections (#13268).
2. **M2. LiteLLM.** Расходы по агенту, прогону и задаче из журнала шлюза. Список моделей берётся
   из шлюза с пометкой «бесплатно / подписка / платно». Ключ на агента. Резервные модели с
   проверкой на циклы.
3. **U1. Telegram.** Длинный ответ делится на несколько сообщений. Файлы — в обычном режиме и
   в режиме своего Bot API. Статус «сейчас делаю…» — одним изменяемым сообщением, результат —
   новым.
4. **R5. Обновление из интерфейса и автообновление:** окно, канарейка, автооткат. Основа —
   вендорский PR #2583.
5. **S3. Песочница на агента.** У каждого агента свой пользователь ОС и доступ только к своему
   профилю. Повышенные права — только явной привязкой. Основа — PR #2988 и #7643.
6. **N1/N2. Побудки и карточки.** Отбитая побудка не теряет задачу. Замок «не повторять» виден
   в интерфейсе и снимается кнопкой. Карточки между агентами доходят до адресата и
   закрываются.
7. **U5. Языки.** Базовый язык интерфейса английский, язык можно выбрать, переводы лежат в
   файлах, русский — первым.
8. **Остальное**, порядок уточняется:
   - R6 — резервная копия данных и настроек вне хоста;
   - S6 — разрешения на инструменты по агенту;
   - S7 — неудаляемый администратор;
   - M3 — лимиты расхода сигналом и стоп-кран холостых циклов;
   - H2 — единый источник инструкций с ревизиями;
   - H3 — доделанный адаптер `hermes_gateway`;
   - N3 — устойчивый шлюз MCP;
   - N4 — побудка с контекстом и живость по прогрессу;
   - U2 — вопросы и согласования в Telegram;
   - U3 — файлы в карточке задачи;
   - U4 — подпись «решение владельца» ставит только владелец;
   - U6 — экран нагрузки сервера;
   - U7 — скорость интерфейса;
   - X1 — трассировка прогонов.

## Вне форка

- **Медиа-инструменты (M4)** — отдельный сервис рядом с доской. В образ Myrmidon не входят:
  ffmpeg, yt-dlp и генераторы медиа в Dockerfile не добавлять.
- **Память агентов** остаётся плагином hindsight. Форк её не заменяет, в CI есть тест
  совместимости плагина (пункт X10 снят).
- **Старая линия наших правок 2026.831.1** не переносится.
