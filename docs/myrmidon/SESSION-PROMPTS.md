# Промпты для запуска сессий по трекам

Шесть облачных сессий Claude Code работают параллельно, по одной на трек. Координатора нет:
согласование между треками описано в [CONVENTIONS.md](CONVENTIONS.md) (разделы 6 и 12).

## Перед запуском (один раз)

**Репозитории.** К каждой сессии подключить оба репозитория:

- `itkadr-git/myrmidon` — рабочий;
- `itkadr-git/myrmidon-deploy` — закрытый, только чтение.

Хуки `SessionStart` из репозитория в сессии с двумя репозиториями не работают. Поэтому
окружение готовит скрипт настройки.

**Окружение `myrmidon`** (создано владельцем 27.09.2026).

- **Сеть:** Custom — отметить «Also include default list of common package managers» и добавить `deb.debian.org`, `security.debian.org` (образ вендора на Debian: без них `docker build` в сессии не пройдёт).
- **Переменные окружения:** `PAPERCLIP_TELEMETRY_DISABLED=1`, `DO_NOT_TRACK=1`, `BASH_DEFAULT_TIMEOUT_MS=300000`, `BASH_MAX_TIMEOUT_MS=1200000`. Секретов в окружении нет.
- **Скрипт настройки** (от root, код выхода 0): ставит Node 24 с nodejs.org со сверкой SHASUMS256 и включает `pnpm@9.15.4` через corepack — вендор требует `node >= 24.11`, в образе сессии только 20–22.

`pnpm install` сессия выполняет сама, в каталоге репозитория.

**Порядок запуска.** Все шесть можно запускать сразу. Но трек 2 должен как можно раньше
влить свой шаг 1 (вендорские коммиты #13891 и #13793), а трек 1 — базовый CI. Остальные
треки начинают с независимых шагов, это прописано в их файлах.

## Трек 1 — платформа

```text
Проект Myrmidon, репозитории itkadr-git/myrmidon (рабочий) и itkadr-git/myrmidon-deploy (закрытый, только читать). Прочитай docs/myrmidon/README.md, ROADMAP.md, CONVENTIONS.md и docs/myrmidon/tracks/1.md и выполни трек 1: CI, образ, проверки лицензий и секретов, совместимость плагинов, телеметрия выключена, минимальный ребрендинг, скрипты выката и отката. Начни с базового CI — остальные треки ждут его. Работай маленькими PR по CONVENTIONS, сливай свои PR сам, когда выполнены условия раздела 6. В открытый репозиторий — никаких секретов и наших внутренних адресов. Вопросы не жди: решай по документам, решения записывай в PR. В конце — итоговый отчёт по разделу «Отчёт» трека.
```
