# Журнал изменений Myrmidon

> English version: [CHANGELOG.md](CHANGELOG.md)

Заметки о выпусках Myrmidon, новее сверху. Версия берётся из git-тега
`myr-v<major>.<minor>.<patch>` (CI вшивает её в образ и в `/api/health`); файла версии,
который надо править, нет. Версия Paperclip в основе — в метке образа
`io.github.itkadr-git.myrmidon.base.paperclip-version`. Подробности процедуры выпуска:
[ci.md](ci.md) и [deploy.md](deploy.md).

## 1.4.0

Всё слитое между тегами 1.3.2 и 1.4.0. Образы доски, dockergate и fleetd этого
выпуска ставятся вместе (см. [deploy.md](deploy.ru.md#выкат-доски-и-dockergate-вместе)).

### Память и изоляция

- Вкладка «Memory» в карточке агента (MEMORY-UI, план 1.4 п. 1): просмотр, выгрузка
  (JSON) и удаление записей банка памяти бота — тем же правилом банка, что форк
  плагина памяти. Удаление записи обратимо (инвалидация с причиной), очистка банка
  целиком — под подтверждением; каждое действие пишется в журнал активности.
  Секция включается парой `MYRMIDON_HINDSIGHT_API_URL` + `MYRMIDON_HINDSIGHT_KEY_SECRET`.
  Руководство: [guides/agent-memory-card.md](guides/agent-memory-card.ru.md) (#258, #265).

### Облачное хранилище

- CLOUD-CONNECTOR часть B: владелец подключает облако из панели — коннектор строит
  authorization URL провайдера с одноразовым state и PKCE, обменивает код и хранит
  полученный набор токенов в секрете компании в хранилище секретов инстанса. В
  собственном состоянии коннектора остаётся только id секрета, поэтому ни один бот
  никогда не держит токен облака, а значение токена не проходит через API панели (#252).

### Выкат и надёжность

- Автоматический откат по здоровью для доски и парка ботов (R5-C). Неуспешная
  проверка здоровья после выката больше не оставляет доску и затронутых ботов на
  сломанном образе. Доска: работа переходит в `rolling_back`, хостовой исполнитель
  запускает `rollback.sh` на образ, который выкат запомнил перед переключением;
  работа заканчивается `auto_rolled_back` (окно обслуживания закрыто) или
  `failed_rollback` (окно оставлено оператору). Боты: неуспешный канарейка или бот
  волны переводит раскат в `rolling_back`; каждый бот, получивший новый образ,
  получает обратно образ своей карточки по одному, и раскат заканчивается
  `rolled_back` с сохранённой исходной причиной. Переключатели (оба по умолчанию
  включены): `MYRMIDON_DEPLOY_AUTO_ROLLBACK` для доски,
  `MYRMIDON_BOT_CANARY_AUTO_ROLLBACK` для парка; хостовая сторона переключателя
  доски — `AUTO_ROLLBACK` в `deploy.env`, обе стороны должны совпадать.
  Автообновление без подтверждения остаётся выключенным (`MYRMIDON_DEPLOY_AUTO_UPDATE=0`);
  см. [SETTINGS.md](SETTINGS.ru.md) (#261).
- Прогоны: запуск из очереди, повторно входящий в start-lock агента, больше не
  ждёт сам себя. Тело блокировки теперь выполняется в кадре async-контекста на
  агента, поэтому вложенный запуск из той же цепочки пропускает ожидание и больше
  не стоит по `AGENT_START_LOCK_STALE_MS` (30 с) на каждой отмене, продвигающей
  очередь (#174).

- RELEASE-GATE: доска и компоненты релиза выкатываются вместе, и это держит сам deploy.sh.
  Он резолвит дайджесты dockergate и fleetd того же релиза (тег `myr-vX.Y.Z` из version-метки
  образа доски, иначе тег `sha-<короткий>` коммита) и отказывает релизу без компонентов в
  реестре ДО каких-либо изменений — инцидент 01.10 выкатил одну доску, а производственный
  dockergate отвергал новый ключ `maxConcurrentRuns` маркера, и все apply ботов падали ~40
  минут. Каждый компонент теперь катится тем же прогоном со своей health-пробой
  (`MYR_<COMPONENT>_HEALTH_URL`), а постдеплойный smoke (`bot-apply-smoke.sh`) ждёт
  повторного применения хотя бы одного ботового контейнера, иначе выкат сообщает DEGRADED с
  командами отката (`rollback-component.sh` на компонент). CI получил контракт applied-маркера:
  маркеры `serializeAppliedMarker()` эмитятся из серверного кода каждого коммита и прогоняются
  через валидатор dockergate — маркер, который валидатор отверг бы, краснит CI до сборки образов (#276).

## 1.3.2

Всё слитое между тегами 1.3.1 и 1.3.2. Образ dockergate этого выпуска ставится вместе с доской.

### Контейнеры ботов

- Сверка больше не пересоздаёт контейнеры ботов, шаблон которых не менялся. dockergate урезал
  `HostConfig.Binds` из ответа на inspect контейнера (A2), а проверка дрейфа шаблона драйвера это
  поле сравнивала, поэтому каждый бот на каждом проходе считался изменившимся: на бою все 51
  контейнер пересоздавались каждые 17–20 минут и прерывали каждый прогон в работе. Ответ A2 снова
  несёт список bind'ов, а контрактный тест гейта сверяет, что все сравниваемые поля переживают
  урезание (список полей эмитит код драйвера, а не скопированная руками фикстура) (#253).
- Каждый дрейф пишет строку журнала с именем поля и обоими значениями
  (`bot container template drift detected`, `details.fields`), так что он диагностируется по
  журналу, а не ценой ещё одного инцидента (#253).
- Проба дескриптора state-DB на пути записи шлюза ограничена по бюджету: проверка поколения
  WAL/SHM теперь ограничена, так что медленная или зависшая файловая система больше не
  останавливает каждую запись бота (#240).
- Вариант образа бота для разработки: доступен третий target сборки с инструментарием
  репозиторного цикла (#238).

### Интерфейс

- Ядро живой консоли экрана браузера: владелец наблюдает и управляет живым браузером, в котором
  авторизуются боты. Реестр, сессии экрана с безопасными таймерами, двухконтурная пауза ботов,
  журнал сессий и очистка данных сайта. См. [guides/browsers.md](guides/browsers.ru.md) (#210).
- Серверное ядро хаба доступов: серверный модуль раздела «Доступы» (секреты, выдача, ротация,
  SSH-ключи) слит. См. [guides/access-hub.md](guides/access-hub.ru.md) (#235).
- Руководство по реестру стека: посеянный список компонентов, `GET /api/myrmidon/stack` и
  `POST /api/myrmidon/stack/refresh`, кэш и настройка сокета Docker. См.
  [guides/stack-registry.md](guides/stack-registry.ru.md) (#243).
- Руководство по хабу доступов приведено в соответствие с слитым серверным модулем (#249).

### Облачное хранилище

- Облачное хранилище с авторизацией владельца и выдачей папок агентам: владелец подключает один
  аккаунт на провайдера, ведёт список доступных папок и выдаёт их агенту, касте или всем с
  режимом только чтение или чтение-запись. Провайдер OneDrive и API под
  `/api/myrmidon/cloud-connector`. См.
  [guides/cloud-files-connector.md](guides/cloud-files-connector.ru.md) (#245).

## 1.3.1

Всё слитое между тегами 1.3.0 и 1.3.1. Выпуск заменяет 1.3.0 и несёт два исправления,
которых в 1.3.0 нет.

### Контейнеры ботов

- dockergate принимает маркер применённого профиля с необязательным ключом
  `maxConcurrentRuns` (целое 1–50), который доска записывает со времён CONCURRENCY-SYNC.
  dockergate версии 1.3.0 требовал ровно три ключа и отклонял каждое применение профиля
  контейнера бота с `tar_content` (`applied_json`), что на свежей установке останавливает
  весь парк. Выкатывайте образ dockergate этого выпуска вместе с доской; подменённый
  вручную образ dockergate больше не нужен. См. [dockergate.md](dockergate.ru.md#маркер-применённого-профиля)
  (#228).
- Канареечный выкат образа ботов: новый образ сначала применяется одному боту-канарейке,
  проверяются его здоровье (Docker HEALTHCHECK плюс окно стабилизации) и дымовой прогон
  против шлюза канарейки, и только затем идут волны по
  `MYRMIDON_BOT_CANARY_WAVE_SIZE` (по умолчанию 4) ботов, по одному за раз. Провал
  канарейки останавливает выкат, не трогая остальной парк; выкат можно прервать.
  Маршруты: `GET/POST /api/myrmidon/bot-canary[/preview|/:id/abort]` (чтение — доска;
  запись — администратор инстанса). По умолчанию всё выключено (`MYRMIDON_BOT_CANARY`).
  Дизайн: [design/bot-canary.md](design/bot-canary.md) (на английском) (#222).
- Настройки бота разрешаются по хосту парка: запись `MYRMIDON_FLEET_HOSTS` может
  переопределить адрес hindsight, базовый адрес LLM-шлюза, дополнительное имя хоста
  доски, корень томов, сеть ботов и список разрешённых образов для ботов, размещённых на
  этом хосте; поле, отсутствующее в записи, берёт значение инстанса. См.
  [SETTINGS.md](SETTINGS.ru.md) (#225).
- Новое руководство: [guides/bot-container-card.md](guides/bot-container-card.ru.md) —
  раздел «Container» карточки агента, предел одновременных прогонов и маркер применённого
  профиля (#219).
- Чтение карточки сверяется в момент прохода, а не по снимку свипа (#237).

### База данных

- Горячие свипы чата и восстановления сравнивают uuid-столбцы как uuid-типизированные
  значения со сторожем вместо текста. Текстовый каст столбца не даёт использовать индекс
  первичного ключа, поэтому каждый проход сканировал таблицу целиком; на бою это держало
  базу доски на 300–400 % CPU. Новые индексы не нужны — сравнения обслуживаются
  индексами первичных ключей (#227).
- Миграция `0286` удаляет самодельные операторские выраженческие индексы
  `myr_hotfix_issue_comments_id_text`, `myr_hotfix_wakeup_id_text` и
  `myr_hotfix_heartbeat_runs_id_text`, созданные вне истории миграций, чтобы остановить
  деградацию. После типизации предикатов они больше не нужны (#227).

### Интерфейс

- Раздел «About Myrmidon» в Instance → General (версия выпуска, коммит, дата сборки,
  отпечаток образа, если задан, версия Paperclip-основы, лицензия и ссылки) и строка
  версии выпуска в подвале сайдбара. Данные отдаёт новый маршрут
  `GET /api/myrmidon/about` (board/agent; анонимный получает 403) (#216).
- Консоль серверов парка: владелец компании открывает терминал зарегистрированного
  сервера парка в браузере (Guacamole с подписанным auth JSON). Новые маршруты
  `GET/PUT /api/myrmidon/fleet/servers`, `POST /api/myrmidon/fleet/console-token`,
  `POST /api/myrmidon/fleet/console-sessions/close`; серверы живут в новой таблице
  `myrmidon_fleet_servers` (миграция `0287`). Раздел — на странице настроек компании.
  Дизайн: [design/server-console.md](design/server-console.md) (на английском) (#232).
- Ключ LLM-шлюза на агента
  (`POST /api/myrmidon/companies/<companyId>/litellm/keys/<agentId>`, `…/rotate`; `GET`
  отдаёт только имя секрета и sha256 значения; выдача и ротация — только доска) и
  проверка цепочек резервных моделей на цикл при сохранении карточки агента (#233).

### Надёжность

- Недоставленная карточка между агентами больше не погибает от перехода статуса задачи:
  карточка доставляется один раз до того, как терминальный переход её финализирует (#234).
- Ядро реестра компонентов стека: `GET /api/myrmidon/stack` отдаёт сид-список
  компонентов с локальным состоянием (версия/коммит/дайджест или честное «неизвестно»), а
  `POST /api/myrmidon/stack/refresh` (только администратор инстанса) пересобирает кэш из
  того, что видит процесс доски; упавшая инфраструктурная проба сохраняет прежний кэш и
  отвечает 503. См. [guides/stack-registry.md](guides/stack-registry.ru.md) (#212).
- Руководства: в руководство хаба доступов добавлено уведомление о доступности (#214).

## 1.2.1

Всё слитое между тегами 1.2.0 и 1.2.1.

### Память и изоляция

- Локальный форк плагина памяти hindsight (`packages/plugins/hindsight-paperclip`, тот же id
  плагина `paperclip-plugin-hindsight`, версия `0.3.0-myrmidon.1`): память каждого агента
  разрешается в его собственный банк из `adapterConfig.hindsight.bankId` карточки или из
  карты `bankByAgentId` конфигурации. Агент без банка закрыт: удержание пропускается с
  предупреждением, а выборка ничего не возвращает — банка по умолчанию нет. Метаданные
  удержания теперь несут имя агента. Установка и обновление — из пути в репозитории; CI
  получил тестовую линию форка и проверки установки на стороне хоста (#150).

### Контейнеры ботов

- Образ бота с Node.js: `/scratch/npm-global/bin` убран из `PATH` — записываемый том в `PATH`
  позволял боту подложить исполняемый файл, и контракт образа dockergate это отклоняет.
  Предустановленные пакеты в `/opt/node-tools` не затронуты; тест Dockerfile теперь проверяет
  `PATH` каждой стадии против политики dockergate (#167).

### Интерфейс

- Фавиконка Myrmidon везде: превью-инстансы ворктри рисуют муравья Myrmidon вместо скрепки
  вендора, а иконки вкладок и веб-манифест отдаются с no-cache, чтобы браузеры их
  перепроверяли (#166).

### Внутреннее

- Набор назначенных агенту инструментов MCP переехал из `heartbeat.ts` в собственный модуль
  (`agent-assigned-tools.ts`) без изменения поведения, чтобы heartbeat и компилятор профиля
  контейнера бота разрешали одно и то же назначение из одного места (#120).

## 1.2.0

Всё слитое после тега 1.1.0, включая исправления, не получившие своего тега.

### Контейнеры ботов

- Свой шлюз инструментов доски у каждого бота: контейнерные боты ходят на доску через свой
  выделенный шлюз.
- Общий сервис медиа-инструментов MCP для контейнерных ботов, с исправлениями инъекции через
  экранирование фильтра, подсчёта квоты каталогов заданий, потоковых конверсий и владения
  spool.
- `dockergate`: прокси Docker со списком разрешённых вызовов для контейнеров ботов.
- Образ бота: вариант с Node.js (`runtime-node`), ssh-клиент и интерпретатор venv для
  пользователя бота.
- Ключи API доски для ботов выдаются с ответственным пользователем.
- Настраиваемый таймаут создания прогона для шлюза hermes (по умолчанию 60 с).
- Тестам сервера больше не нужен настоящий контейнер для обратной связи о запуске контейнера.

### Память и изоляция

- Список разрешённых банков hindsight и области наблюдения в профилях ботов, плюс инструмент
  разделения банков при переносе памяти.
- Вызовы `apiRoute` плагинов привязаны к области вызова.

### Побудки и heartbeat

- Аварийная остановка прогонов, которые осушаемая пауза оставила дорабатывать: на странице
  агента, пока он на паузе и живые прогоны ещё есть, висит баннер с кнопкой остановки и
  подтверждением, а `POST /api/myrmidon/agents/:id/emergency-stop` отменяет их немедленно тем
  же кодом `agent_paused`, что и отмена при паузе, — статус самого агента не меняется (#173).
  Руководство оператора: [guides/emergency-stop.ru.md](guides/emergency-stop.ru.md).
- Побудки продолжения: исправлены проход по порогу возраста и завершение прямой доставки.
- Задачи, оставленные паузой оператора, будятся пачками при снятии паузы.
- Настраиваемый потолок межзадачного влияния.
- Heartbeat журналирует нечитаемый лимит памяти cgroup; потолок задокументирован.
- Семантика флагов-выключателей покрыта матрицей тестов и стражем документации;
  задокументировано, что перенос бюджета L2 действует только для L1 и что бюджет повторов
  вендора начинается заново у преемника.

### Выкат

- Выкат снимает режим обслуживания при таймауте слива.
- Задокументировано, что миграции базы должны быть только аддитивными.

### Процесс

- Процедура приёма записей в план и сканер текста для записей плана.
- Обёртка сканирования публикаций для текстов PR и задач.
